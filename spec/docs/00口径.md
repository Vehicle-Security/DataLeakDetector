# DataLeakDetector 统一口径

本文档定义项目中“敏感源”“传播”“外发”“确认泄露”“可疑行为”和“正常行为”的统一语义。日志挖掘、VLM、事件关联、污点推理、实验标注和报告展示均应遵循本口径；各模块不得自行扩展最终结论的含义。

## 1. 基本对象

| 对象       | 定义                                       | 说明                                                                             |
| ---------- | ------------------------------------------ | -------------------------------------------------------------------------------- |
| 原始敏感源 | 维护在敏感文件配置中的原始文件             | 是检测链路唯一允许的初始敏感对象；例如原始合同、客户表、薪资表、源码             |
| 派生载体   | 由原始敏感源经可追溯操作形成的对象         | 例如复制件、另存 PDF、导出文件、压缩包、截图、剪贴板内容；不能作为新的初始敏感源 |
| 传播步骤   | 使敏感内容改变载体、进程或可访问位置的操作 | 例如复制、粘贴、另存、导出、压缩、剪贴板跨进程传递、截图                         |
| 外部汇聚点 | 可能使数据离开受控端或暴露给外部主体的通道 | 例如邮件、即时通信、AI 对话、网盘、代码托管、网页提交、外接设备、屏幕共享        |
| 证据链     | 由日志、视觉观察和关联事实组成的可回溯路径 | 最终泄露判定必须能回溯到原始敏感源                                               |

`groundtruth.json` 不属于检测输入，也不能用于补全敏感源、文件血缘或外发证据；它只用于检测结束后的评测对照。

## 2. 什么算敏感数据传播

敏感数据传播是指原始敏感源或已绑定派生载体发生了内容、文件或进程层面的转移，但尚未必然进入外部汇聚点。以下操作属于传播或派生线索，而非单独的确认泄露：

| 类别       | 典型操作                                     | 结果                                                 |
| ---------- | -------------------------------------------- | ---------------------------------------------------- |
| 文件派生   | 复制、另存、导出、格式转换、打印为 PDF、压缩 | 形成或更新派生文件                                   |
| 内容派生   | 提取文本、翻译、手工录入、注释、隐写         | 内容形态发生变化，需后续关联                         |
| 跨进程传播 | 剪贴板写入/读取、应用间粘贴                  | 内容由源应用进入另一应用                             |
| 屏幕采集   | 截图、录屏、屏幕捕获                         | 形成图像或视频载体                                   |
| 本地转移   | 拷贝到本地目录、临时目录或虚拟机共享位置     | 仅在能够继续连接至外部汇聚点时才可构成泄露链的一部分 |

传播步骤可作为 `TransferFile`、`CrossProcessTransfer`、`ClipboardWrite` 或 `ClipboardRead` 等事实进入推理器。仅发生传播并不能得出“已泄露”。

## 3. 什么算外发

外发是指受控敏感数据或其已绑定派生载体被实际交给、提交给、展示给或同步至外部汇聚点。外发的核心不是“界面具备传输能力”，而是存在可验证的实际操作状态和敏感源绑定。

### 3.1 外发通道

| 通道                 | 典型外发动作                                     | 不足以认定外发的情况                                         |
| -------------------- | ------------------------------------------------ | ------------------------------------------------------------ |
| 邮件                 | 添加敏感附件并发送，或发送包含敏感内容的邮件     | 仅打开邮箱、仅显示附件按钮、仅停留在写信页                   |
| 即时通信 / 协作工具  | 上传文件、发送附件、粘贴敏感内容并发送           | 仅打开会话、仅展示发送功能、未提交的输入框                   |
| AI 对话              | 上传敏感文件，或粘贴敏感内容并提交提示词         | 仅访问 AI 页面、仅打开菜单、未提交草稿                       |
| 网盘 / 云同步        | 将敏感文件放入同步队列、上传完成或提交上传       | 仅打开网盘、仅显示拖放区域、仅选中未提交文件                 |
| 网页、社区、代码托管 | 表单提交、内容发布、代码推送或上传               | 仅浏览页面、仅编辑但未提交、仅显示发布按钮                   |
| 外接设备 / 蓝牙      | 将敏感文件复制或发送至外接设备并出现传输状态     | 仅连接设备、仅打开传输工具、无文件或进度证据                 |
| 屏幕共享             | 共享状态已启动，且敏感文件在共享期间被打开或可见 | 仅进入会议、仅看到“共享屏幕”按钮、敏感文件未在共享期间出现 |

### 3.2 操作状态

外发证据应区分下列状态：

| 状态            | 语义                                         | 口径处理                                     |
| --------------- | -------------------------------------------- | -------------------------------------------- |
| `selected`    | 文件已选择、附件已加入、内容已进入待提交区域 | 是准备或未完成外发线索；通常不能单独确认泄露 |
| `submitted`   | 用户已点击发送、上传、提交或发布             | 可作为外发证据，仍需敏感源和时间链绑定       |
| `in_progress` | 传输、同步或共享正在进行                     | 可作为外发证据，仍需敏感源和时间链绑定       |
| `completed`   | 传输、发送或提交完成                         | 最强的外发状态，仍需敏感源和时间链绑定       |
| `failed`      | 外发尝试失败                                 | 记录为可疑或失败尝试，不认定已泄露           |
| `unknown`     | 无法从日志或界面确认实际状态                 | 不作为确认泄露的充分证据                     |

对于两步上传或表单发布流程，“选择文件”与“上传/提交”必须分开处理。对于屏幕共享，外发证据是“共享已启动 + 敏感内容在共享期间暴露”的组合，而非单一的共享入口界面。

## 4. 最终结论口径

检测器最终只输出以下三类结论：

| 结论                             | 触发条件                                           | 含义                                                       |
| -------------------------------- | -------------------------------------------------- | ---------------------------------------------------------- |
| `data_leak_risk_detected`      | 存在至少一条完整`LeakPath`                       | 已确认存在从原始敏感源到外部汇聚点的可回溯传播路径         |
| `suspicious_behavior_detected` | 没有完整`LeakPath`，但存在与敏感源绑定的可疑事实 | 发现隐藏转换、未完成外发、失败外发或其他风险行为，需要复核 |
| `no_confirmed_data_leak`       | 不存在完整泄露路径，也不存在与敏感源绑定的可疑事实 | 未发现可确认泄露或敏感风险行为                             |

确认泄露必须同时满足：

1. **源绑定**：路径起点是维护的原始敏感源，或派生载体可被回溯至该敏感源。
2. **外发证据**：存在实际外发操作或共享暴露状态，而非单纯风险应用、菜单或能力展示。
3. **完整连通性**：敏感源、传播步骤和外部汇聚点在事实图中连通。
4. **时间合理性**：路径按操作发生顺序前进，不接受通过未来事件反向补出的传播关系。

形式化地，确认泄露路径可写为：

```text
SensitiveSource --(zero or more propagation steps)--> Carrier
                --(confirmed outbound action)-------> ExternalSink
```

其中 `Carrier` 可以等于原始敏感源，也可以是由其派生的文件、内容或屏幕载体。

## 5. 可疑行为口径

可疑行为用于保留风险线索，不等同于确认泄露。它必须与敏感源或其可追溯派生载体存在绑定，不能因为用户传输了普通文件就触发数据泄露风险。

典型情形包括：

- 敏感内容被截图、导出、压缩、转换或以其他方式隐藏处理，但尚未观察到外部去向；
- 敏感文件已被选为附件、放入上传区域或粘贴至外部应用，但没有提交、传输或共享完成证据；
- 已观察到外发操作，但操作失败、取消或无法确认最终状态；
- 发生了与敏感源绑定的异常跨进程传播，且目的应用或目标位置不明确。

以下情形不应单独构成可疑行为：打开浏览器、登录网盘、进入会议、连接外设、存在“上传/发送”按钮，或没有敏感源绑定的普通文件传输。

## 6. 证据优先级与冲突处理

不同证据来源承担不同职责：

| 证据来源     | 主要证明内容                                      | 不应单独证明的内容                           |
| ------------ | ------------------------------------------------- | -------------------------------------------- |
| 终端日志     | 时间、文件访问、进程、应用切换、显式上传/发送事件 | GUI 中是否真正选中、粘贴、点击或显示敏感内容 |
| 关键帧 / VLM | 界面状态、附件、输入框、发送/共享状态、可见内容   | 未出现在画面或上下文中的文件血缘             |
| 文件血缘     | 原始敏感源与派生载体的关联                        | 外发动作是否实际发生                         |
| 污点推理     | 路径连通性、顺序和最终裁决                        | 凭空生成新的文件关系或 GUI 行为              |

证据冲突时遵循保守原则：无法同时满足源绑定、外发证据和时间连通性时，降级为可疑行为或不报告确认泄露。日志规则和 VLM 都可提出风险线索；确认结论由确定性的完整路径推理给出。

## 7. 检测口径与标注口径

`groundtruth.json` 的标签仅用于评测。其文本中命中“直接外发、邮件外发、复制内容外发、内容外发、完成外传、上传、发送、屏幕共享展示敏感文件”等词时，评测侧归为泄露；命中“潜在隐藏行为、隐藏行为、可疑”时归为未知风险；命中“正常操作、正常”时归为非泄露。

检测器不读取这些标签参与推理，并且报告中应分别保留：

- `detector_conclusion`：来自事件关联与污点推理的实际检测结论；
- `groundtruth_conclusion`：仅用于实验对照的标注结论。

二者不一致时，应作为误报、漏报或口径/证据缺失问题分析，不能以 ground truth 反向修改检测证据。

## 8.消融实验口径

| 变体                  | 应保留                            | 应移除                                                  | 核心目的                             |
| --------------------- | --------------------------------- | ------------------------------------------------------- | ------------------------------------ |
| GUI only              | VLM 对屏幕帧的识别、相同的帧预算  | 日志挖掘、日志引导的选帧、FrameAnalyzer 的融合/日志锚定 | 只看 GUI 画面能做到什么程度          |
| w/o File Lineage      | 日志、VLM、事件关联、Datalog 推理 | 派生文件/载体到原敏感源的跨事件关系                     | 验证“文件血缘”对多跳传播还原的贡献 |
| w/o Datalog Reasoning | 日志、VLM、事件关联、文件血缘     | 全局事实闭包和污点路径推理                              | 验证 Datalog 对跨步骤链路推理的贡献  |

逐案复核方法：

1. 对每个案例读取新跑 Full 的 leak_reasoner.leak_paths。
2. 与 case_debug 的 leak_paths 对照“敏感源 → 派生/最终载体 → 外发渠道”的语义链。
3. 不要求绝对路径逐字符一致：文件名、目录、分隔符差异，以及派生载体的表示差异，不单独判错。
4. 必须能语义上对应最终外发载体和渠道。
5. 虚拟机内未落盘中间载体不单独判错。
6. stage5/U4-Bluetooth-SensitiveLeak-3 的敏感文件 JSON 源文件问题不单独判错；新跑的“机密合同.pdf → 普通文件.docx → removable_media”按正确处理。
7. stage4/4-1 在新跑与 case_debug 中均无 leak_paths，保留为已有失分。

为什么不用严格脚本：

- tools/evaluate_table5.py 要求同一条路径精确包含 groundtruth 每一步的 sensitive_file，并以该字段匹配 leaked_file/sink。
- groundtruth 经常把原始文件写在泄露操作中，而实际正确链路输出的是派生文件；绝对路径与仅文件名也会被误判。
- 例如 stage4/10-2 实际识别到两个分片经邮件外发，但严格脚本要求原始 xlsx 作为 sink，误判失败。
