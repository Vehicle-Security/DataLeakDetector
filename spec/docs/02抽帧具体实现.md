# 抽帧具体实现

## 1. 实现范围

本文说明 DataLeakDetector 如何从 `AnalysisWindow` 和 MP4 生成 `raw_all` 候选帧。实现位于 `main/data_leak_detector/frame_analyzer/frames.py`，入口为 `select_keyframes_detailed()`。

这里的 `raw_all` 是**全局去重前的窗口候选帧集合**，不是整段视频的所有解码帧，也不是所有时间探针的机械保存结果。每个窗口内部仍会执行必要的精简：动作锚点和动作状态强制保留，普通画面则需要满足画面变化和最小时间间隔条件。`raw_all` 随后才交给全局去重生成 `raw`；该部分见 `02帧去重具体实现.md`。

```text
AnalysisWindow[] + MP4
  -> 动作感知时间探针
  -> OpenCV 按时间解码
  -> 窗口内候选筛选与预算
  -> raw_all (selection.raw_keyframes)
  -> 全局去重
  -> raw (selection.keyframes)
```

## 2. 调用链

视觉编排入口 `_load_or_select_keyframes()` 先取得日志挖掘生成的窗口；若没有结果型动作窗口，则添加稀疏的视频覆盖窗口。之后调用：

```python
selection = select_keyframes_detailed(video_path, windows, config)

raw_all = selection.raw_keyframes
raw = selection.keyframes
duplicates = selection.duplicates
```

主要流程如下：

```text
open video with cv2.VideoCapture
read FPS and frame count, derive duration_ms

for each AnalysisWindow:
    if it is an activity window:
        reduce it to context needed by overlapping strong actions
    clamp window to video duration
    timestamps = probe_timestamps(window)
    decoded = read_frames_for_timestamps(timestamps)
    candidates += select_window_candidates(decoded, window)

raw_all = [candidate.frame for candidate in candidates]
raw, duplicates = global_deduplicate(candidates)
return KeyFrameSelection(raw, raw_all, duplicates, warnings)
```

若视频路径缺失、不是普通文件、OpenCV 未安装、视频无法打开或 FPS 不可用，函数返回空选择并在 `warnings` 中记录原因，不会让整个检测流水线异常退出。

## 3. 时间探针生成

### 3.1 基础规则

`_probe_timestamps()` 从窗口的动作阶段和锚点生成探针时间。探针上限为：

```text
probe_limit = max(
    window.max_keyframes * frame_probe_multiplier,
    number_of_current_timestamps,
    3 * number_of_anchors,
)
```

其中，动作状态时间和锚点时间是必保留位置；可选的稠密探针超出上限时，会被时间均匀压缩，而不会丢弃必保留位置。

对每个普通锚点，至少加入：

```text
anchor - step_ms, anchor, anchor + step_ms
```

非活动窗口还会用 `_dense_probe_timestamps()` 在整个窗口范围内均匀补点。活动窗口采用更保守的 `_activity_probe_timestamps()`：仅在前台外部应用存在时保留活动区间起点、中点、终点，或围绕已有锚点保留上下文，避免长时间办公阅读占用过多解码预算。

### 3.2 动作特定偏移

`_phase_timestamps()` 根据 `action_phases` 选择不同的相对偏移表。动作阶段按偏移分为 `pre`、`at`、`immediate`、`post` 和 `result`，让后续候选选择能优先保留状态链，而不是只取日志发生的单一时刻。

| 动作 | 探针特点 | 目的 |
| --- | --- | --- |
| `file_selected` | 锚点前约 2 秒至锚点后约 30 秒 | 捕获文件选择、附件出现与延迟的发送界面 |
| `upload` / `send` / `removable` | 锚点前后数秒至十秒 | 捕获点击、进度、发送或设备传输状态 |
| `clipboard` | 锚点前数秒到后约 30 秒 | 保留源内容、切换应用和后续粘贴机会 |
| `paste` | 锚点后密集到约 15 秒 | 捕获可能仅短暂出现的粘贴预览与提交状态 |
| `derive` | 锚点前约 20 秒到后约 10 秒 | 导出、压缩等日志可能晚于实际界面动作 |
| `capture` | 以采集前画面为重点 | 验证被截图或录制的敏感内容是否可见 |
| `screen_share` | 锚点前后约十余秒 | 捕获共享启动与共享期间状态 |
| 会话上下文 | 仅保留会话开始、状态变化和结束锚点 | 建立外部应用连续证据包 |

当前的具体偏移值定义在 `frames.py` 顶部常量中，例如 `_FILE_SELECTION_OFFSETS_MS`、`_PASTE_OFFSETS_MS` 和 `_DERIVATION_OFFSETS_MS`。改变动作偏移会直接改变 `raw_all` 的候选分布，应与对应场景测试一起更新。

## 4. 视频解码

### 4.1 OpenCV 时间定位

视频通过 `cv2.VideoCapture` 打开。对于孤立探针，`_seek_read_frame()` 设置 `CAP_PROP_POS_MSEC` 后读取一帧：

```python
capture.set(cv2.CAP_PROP_POS_MSEC, float(timestamp_ms))
ok, frame = capture.read()
```

对于时间相近的探针，重复 seek 的开销较高，也更容易出现关键帧定位不稳定。`_timestamp_groups()` 按 `frame_sequential_gap_ms` 将相邻时间点分组；组内只 seek 一次起始位置，再顺序解码至各目标时间。

```text
groups = partition(sorted(timestamps), gap <= frame_sequential_gap_ms)
for group in groups:
    if one timestamp:
        seek and read
    else:
        seek to group start and sequentially read frames
retry only missing timestamps with direct seek
```

顺序解码的时间容差至少为一个视频帧间隔或 50 ms。对部分编解码器，顺序读取返回的位置可能不可靠，因此函数只对缺失的证据时间点进行 direct seek 重试。

### 4.2 窗口与视频时长对齐

视频时长由 `frame_count / fps` 计算。每个窗口在解码前通过 `_clamp_window_to_duration()` 裁剪到 `[0, duration_ms]`，同时裁剪锚点、动作阶段和活跃区间，避免对负时间或视频结束后的时间点请求解码。

## 5. 窗口内候选帧筛选

`_select_window_candidates()` 接收“已解码帧 + 一个窗口”，逐帧构造 `_FrameCandidate`。每帧先缩放至 `160 x 90` 灰度图，再计算：

```text
pixel_delta   = mean(abs(previous_gray - current_gray)) / 255
entropy       = Shannon entropy(current_gray histogram)
entropy_delta = abs(entropy - previous_entropy) / 8
score         = max(pixel_delta, entropy_delta)
hash          = 8 x 8 average hash
```

候选保留规则如下：

```text
force_anchor = timestamp is near an AnalysisWindow anchor
force_state  = timestamp matches a planned action-state timestamp

if force_anchor or force_state:
    keep unconditionally
elif exact local duplicate:
    discard
elif score < window.diff_threshold and entropy_delta < frame_entropy_change_threshold:
    discard
elif frame_min_keep_gap_ms is configured and gap is too small:
    discard
else:
    keep as visual-change evidence
```

保留帧会写入临时目录，并生成：

```text
frame_id   = frame_{window_index}_{candidate_index}
reason     = strong:action_state:<action>:<role>
          | strong:anchor
          | strong:visual_change
window_id  = window_{window_index}
```

动作锚点和动作状态在窗口内被优先保留，即使画面变化很小。这一设计避免了“点击前后的 UI 像素几乎不变”导致关键证据被局部差分过滤掉。

## 6. 窗口级语义聚焦与预算

初步保留的候选帧还会经过两层窗口内控制，这两层仍属于 `raw_all` 生成，而不是全局 `raw_all -> raw` 去重：

1. `_focus_semantic_action_phases()`：针对每个动作阶段，保留代表性的动作前、即时、动作后和晚期结果帧。粘贴优先保留约 `+2.25s` 的常见渲染状态；文件选择和剪贴板保留更多后续状态；会话上下文只保留最接近锚点的帧。
2. `_budget_window_candidates()`：当一个窗口超过 `max_keyframes` 时，优先分配给动作状态、动作后结果、外部会话上下文，再用时间均匀分布和画面评分填满剩余预算。

伪代码如下：

```text
if candidates exceed window budget:
    retain mandatory action states or anchors
    reserve slots for post-action visual changes
    retain session start/state/end context when present
    fill remaining slots with temporal spread, then high score / high entropy frames
```

因此，`selection.raw_keyframes` 是“窗口内已具备状态语义和预算控制的全部候选帧”；不同窗口的相似帧、重叠窗口导致的重复帧和全局近似帧仍会保留到下一步处理。

## 7. `raw_all` 制品与后续边界

`export_vision_artifacts()` 将 `selection.raw_keyframes` 复制至 `keyframes_raw_all/`，并将全局去重后的 `selection.keyframes` 复制至 `keyframes_raw/`。同时保存 `keyframe_duplicates.json` 和 `artifact_manifest.json`，便于比较两个阶段的帧数与被淘汰原因。

抽帧阶段之后的边界为：

```text
raw_all = per-window candidates after local selection and budgeting
raw     = raw_all after global visual/semantic deduplication
VLM     = raw after frame-budget sampling; no separate visual deduplication currently
```

`vision_precompute.json` 可缓存窗口和 `raw` 关键帧，供提示词或 VLM 参数调试复用；缓存命中时不会重新解码视频。

## 8. 关键参数

| 环境变量 | 默认值 | 作用 |
| --- | ---: | --- |
| `DLD_FRAME_PROBE_MULTIPLIER` | `6` | 候选探针数相对窗口帧预算的放大倍数 |
| `DLD_FRAME_SEQUENTIAL_GAP_MS` | `5000` | 相邻时间点可进行顺序解码的最大间隔 |
| `DLD_STRONG_FRAME_STEP_MS` | `250` | 强窗口锚点邻近帧间隔 |
| `DLD_WEAK_FRAME_STEP_MS` | `2000` | 弱窗口锚点邻近帧间隔 |
| `DLD_FRAME_DIFF_THRESHOLD` | `0.08` | 常规窗口的画面变化阈值 |
| `DLD_STRONG_FRAME_DIFF_THRESHOLD` | `0.015` | 强窗口的画面变化阈值，较低以避免漏掉细小 UI 变化 |
| `DLD_FRAME_EXACT_DUPLICATE_THRESHOLD` | `0.001` | 窗口内精确重复帧阈值 |
| `DLD_FRAME_ENTROPY_CHANGE_THRESHOLD` | `0.04` | 画面变化较小时，用信息熵变化补充保留判定 |
| `DLD_FRAME_MIN_KEEP_GAP_MS` | `0` | 非强制候选帧之间的最小时间间隔；`0` 表示不额外限制 |
| `DLD_MAX_KEYFRAMES_PER_STRONG_WINDOW` | `18` | 强窗口内候选帧预算 |
| `DLD_MAX_KEYFRAMES_PER_MEDIUM_WINDOW` | `2` | 中等窗口内候选帧预算 |
| `DLD_MAX_KEYFRAMES_PER_WEAK_WINDOW` | `2` | 弱窗口内候选帧预算 |

`DLD_FRAME_NEAR_DUPLICATE_THRESHOLD`、`DLD_FRAME_HASH_DISTANCE_THRESHOLD` 和 `DLD_FRAME_ENTROPY_DUPLICATE_THRESHOLD` 主要用于下一阶段的全局去重，不是本章窗口内候选筛选的主阈值。
