## 3. Release Mode

固定全量起点是 `spec\data\nas_samples`。`--case-root` 会递归发现其中所有同时包含 `logs` 和 `video` 的 case；当前共 309 个。

### Neo4j 预热

先启动 Neo4j，并用单 worker 顺序导入所有日志。预热不启用视觉模型，不消耗 VLM 配额；后续全量运行会复用相同 case/log 指纹，避免并发导入超时。

```powershell
.\tools\start_neo4j.ps1

$python = ".\.venv\Scripts\python.exe"
$env:DLD_NEO4J_REUSE_IMPORT="1"
$env:DLD_NEO4J_LOG_MINER_BATCH_SIZE="500"

& $python tools\warm_neo4j.py `
  --case-root "spec\data\nas_samples" `
  --output "artifacts\all_data_neo4j_warmup\progress.json"
```

终端会显示当前 case 和 `batch=... events=.../...`；实时状态写入 `artifacts\all_data_neo4j_warmup\progress.json`。预热结束后确认其中 `failed_cases=0`。

### 全量 Release 矩阵

### 第一阶段：视觉预处理缓存

内存版适合最快预处理：

```powershell
$python = ".\.venv\Scripts\python.exe"
& $python main/run_e2e.py `
  --case-root "spec\data\nas_samples" `
  --case-workers 4 `
  --release `
  --release-precompute-only `
  --no-neo4j-log-miner `
  --vision `
  --vision-mode hybrid `
  --output-dir "artifacts\all_data_release_matrix"
```

终端会输出 `precompute [n/309] case=...`；缓存位于 `artifacts\all_data_release_matrix\vision_precompute`。已有 `artifacts\all_data_neo4j_warmup` 时无需在此阶段再次查询 Neo4j；预热图保留给离线图查询，避免与并行视频/OCR 竞争 Bolt 连接。

Neo4j 版使用预热图计算窗口和 active app。它与内存版写入相同缓存格式，但本地 Neo4j 应顺序查询：

```powershell
$python = ".\.venv\Scripts\python.exe"
& $python main/run_e2e.py `
  --case-root "spec\data\nas_samples" `
  --case-workers 1 `
  --release `
  --release-precompute-only `
  --release-precompute-neo4j-log-miner `
  --vision `
  --vision-mode hybrid `
  --output-dir "artifacts\all_data_release_matrix_neo4j"
```

两种第一阶段应使用不同 `--output-dir`，不要混用同一个缓存目录。

### 第二阶段：复用缓存跑 VLM 矩阵

```powershell
$python = ".\.venv\Scripts\python.exe"
$strategies = @("direct_keyframes", "ocr_all", "ocr_triage")
$grids = @(1, 2, 3)
& $python main/run_e2e.py `
  --case-root "spec\data\nas_samples" `
  --case-workers 4 `
  --release `
  --release-vlm-strategies $strategies `
  --release-vlm-grids $grids `
  --output-dir "artifacts\all_data_release_matrix" `
  --no-neo4j-log-miner `
  --vision `
  --vision-mode hybrid `
  --max-vlm-frames -1 `
  --vlm-workers 10 `
  --vlm-fast-dispatch
```

第二阶段会显示 `release variant=i/9`、`started case=...` 和 `[n/309] completed case=...`；缺失缓存 case 会先补预处理，已有缓存不会重复视频/OCR。

所有 309 个 case 从同一固定根目录运行。命令会先一次性完成日志、非均匀关键帧和 OCR 预处理，并将可复用图片与 OCR 结果写入 `vision_precompute`；随后九个策略/grid 组合只执行 VLM、关联和判定，不再重复视频解码或 OCR。每个阶段内部 4 个 case 并行准备，所有 VLM batch 进入进程级共享队列，由 Coding 10 路加 Token 10 路固定 worker 消费。全量 VLM 批处理强制使用内存日志挖掘，避免本地 Neo4j 在并发查询时出现 Bolt 超时。

```powershell
$python = ".\.venv\Scripts\python.exe"
$strategies = @("direct_keyframes", "ocr_all", "ocr_triage")
$grids = @(1, 2, 3)

& $python main/run_e2e.py `
  --case-root "spec\data\nas_samples" `
  --case-workers 4 `
  --release `
  --release-vlm-strategies $strategies `
  --release-vlm-grids $grids `
  --output-dir "artifacts\all_data_release_matrix" `
  --release-precompute-neo4j-log-miner `
  --no-neo4j-log-miner `
  --vision `
  --vision-mode hybrid `
  --max-vlm-frames -1 `
  --vlm-workers 10 `
  --vlm-fast-dispatch
```

该命令会执行 `309 x 3 x 3` 个 case/组合分析，实际耗时和 VLM 成本较高。完整明细和便于横向比较的扁平结果分别写入：

```text
artifacts\all_data_release_matrix\release_matrix_report.json
artifacts\all_data_release_matrix\release_matrix_comparison.json
artifacts\all_data_release_matrix\release_variants\<strategy>_grid<grid>.json
```

每个 `strategy + grid` 方案在完成其全部 309 个 case 后会立即写入 `release_variants` 下独立的 JSON。`release_matrix_comparison.json` 的 `variant_rows` 是每个方案一行的正确率、VLM 帧数和耗时汇总；`case_rows` 是每个 case/方案一行的检测结论、标注结论和 `detector_correct`。每完成一个方案就会刷新一次，可在九组尚未全部结束时直接对比已完成的结果。

运行期间终端会输出当前策略组合、已开始的 case，以及每个完成或失败的 case。实时状态会原子写入：

```text
artifacts\all_data_release_matrix\release_progress.json
```

其中 `variant` 表示当前第几个策略/grid 组合，`running_cases` 是正在处理的 case，`queued_cases` 是尚未开始的数量，`last_case` 和 `recent_cases` 用于查看刚完成或失败的 case。完成记录的 `detector_correct=true/false` 表示检测结论与二元 groundtruth 是否一致；`null` 表示该样本没有可评分的二元标注。

## 5. 快速终止运行

当全量任务无法及时响应键盘中断时，先终止本项目的 `run_e2e.py` 进程及其子进程：

```powershell
$all = Get-CimInstance Win32_Process
$ids = [System.Collections.Generic.List[int]]::new()

$all |
  Where-Object {
    $_.Name -match "^python.*\.exe$" -and
    $_.CommandLine -match "(?i)(^|[\s\"])main[\\/]run_e2e\.py([\s\"]|$)"
  } |
  ForEach-Object { [void]$ids.Add([int]$_.ProcessId) }

do {
  $children = $all | Where-Object {
    $ids.Contains([int]$_.ParentProcessId) -and -not $ids.Contains([int]$_.ProcessId)
  }
  $children | ForEach-Object { [void]$ids.Add([int]$_.ProcessId) }
} while ($children)

$ids | Sort-Object -Descending | ForEach-Object {
  Stop-Process -Id $_ -Force -ErrorAction SilentlyContinue
}
```

紧急情况下可以直接终止全部 Python 进程，但这会同时停止无关的测试、服务和脚本：

```powershell
Get-Process python, python3 -ErrorAction SilentlyContinue | Stop-Process -Force
```
