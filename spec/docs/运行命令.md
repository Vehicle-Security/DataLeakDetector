# 运行命令

本文放平常调试 DataLeakDetector 最常用的命令。默认工作目录是仓库根目录：

```powershell
cd D:\Projects\Job\DataLeakDetector
```

本文命令默认使用仓库内虚拟环境。OCR、PaddleOCR CUDA、Neo4j 等实验依赖装在 `.venv` 或本地服务里时，优先用 `$python` 调用，避免误用系统 Python：

```powershell
$python = ".\.venv\Scripts\python.exe"

# 也可以激活后再直接用 python
# .\.venv\Scripts\Activate.ps1
```

## 1. 参数速查

| 参数                                      | 作用                                                                  | 常用场景                              |
| ----------------------------------------- | --------------------------------------------------------------------- | ------------------------------------- |
| `--case` / `-c`                       | 指定 `spec/data` 样例目录，自动发现日志、视频、groundtruth 和敏感源 | 跑真实样例时优先用这个                |
| `--log` / `-l`                        | 直接指定 JSON/JSONL 日志文件                                          | 跑自定义日志或临时最小样例            |
| `--video` / `-v`                      | 直接指定视频文件                                                      | 配合 `--log` 使用                   |
| `--groundtruth`                         | 指定 groundtruth 文件                                                 | 配合 `--log` 使用时补评估口径       |
| `--output-dir` / `-o`                 | 输出报告和 artifact 的根目录                                          | 建议每轮实验单独一个目录              |
| `--sensitive-file`                      | 手工指定敏感源文件，可重复                                            | 没有 groundtruth 或想额外指定敏感源   |
| `--observations`                        | 读取预先生成的 frame observations JSON                                | 跳过视觉模型，复用已有观察            |
| `--vision`                              | 打开抽帧、OCR/VLM 视觉链路                                            | 需要视频证据时使用                    |
| `--vision-mode ocr`                     | 只跑 OCR，不调用 VLM                                                  | 非 VLM baseline、OCR 调参             |
| `--vision-mode hybrid`                  | 先 OCR，再选择部分帧送 VLM                                            | 正常视觉增强检测、VLM-only 评估       |
| `--vision-mode vlm`                     | 允许 VLM 路径                                                         | VLM 实验；仍依赖抽帧和候选帧选择      |
| `--max-vlm-frames 0`                    | 不发送任何帧给 VLM                                                    | 确保 OCR-only / 非 VLM                |
| `--max-vlm-frames N`                    | 最多发送 N 张 OCR 候选帧给 VLM                                        | 控制费用和速度                        |
| `--vlm-frame-strategy ocr_triage`       | OCR 后只把风险/低置信/强锚点帧送 VLM                                  | 默认策略；部分提前判定不走 VLM        |
| `--vlm-frame-strategy ocr_all`          | OCR 后保留的帧都允许送 VLM                                            | 看“经过 OCR 筛帧但不跳过 VLM”的效果 |
| `--vlm-frame-strategy direct_keyframes` | 不经过 OCR，直接把关键帧送 VLM                                        | 看纯关键帧 VLM 的效果                 |
| `--vlm-grid-size N`                     | 把选中的 VLM 候选帧合成 N×N grid 图再请求模型                        | 降低请求图片数、观察合帧效果          |
| `--vlm-workers N`                       | 把 VLM 请求帧拆成 N 批并发请求                                        | 批量评估时加速；注意 API 并发/限流    |
| `--no-non-vlm`                          | 关闭确定性 OCR/log 证据，只让 VLM 观察进入关联推理                    | 单独评估 VLM 准确性                   |
| `--vlm-dry-run`                         | 只写 VLM request/候选帧 artifact，不调用模型 API                      | 调候选帧、prompt、成本前置检查        |
| `--neo4j-log-miner`                     | 用 Neo4j 做日志挖掘/抽帧窗口                                          | 长日志、固定样例复跑                  |
| `--no-reuse-neo4j-import`               | 禁止复用 Neo4j 日志导入                                               | 调 importer 或 schema 时使用          |
| `--neo4j`                               | 把最终报告写入 Neo4j 图                                               | 需要图查询/可视化报告时使用           |
| `--neo4j-strict`                        | Neo4j 写入失败时直接失败                                              | CI 或确认 Neo4j 必须可用时使用        |

注意：进程环境变量优先级高于 `.env`。当前 `.env` 的常用实验默认是 `DLD_OCR_PROVIDER=paddleocr` 和 `DLD_NEO4J_LOG_MINER=1`；如果在 PowerShell 里临时设置了同名变量，会覆盖 `.env`。

如果本轮确实不启动 Neo4j，可以显式关闭 log miner：

```powershell
$env:DLD_NEO4J_LOG_MINER="0"
```

## 2. 常用环境变量

### OCR / 抽帧

```powershell
$python = ".\.venv\Scripts\python.exe"
$env:DLD_OCR_PROVIDER="paddleocr"     # 默认用虚拟环境里的 PaddleOCR
$env:DLD_OCR_USE_CUDA="1"             # PaddleOCR / RapidOCR 统一 CUDA 开关
$env:DLD_OCR_WORKERS="1"              # PaddleOCR 先用 1，避免多引擎占满显存
$env:DLD_OCR_MAX_IMAGE_SIDE="1280"    # 当前 .env 默认值
$env:DLD_NEO4J_LOG_MINER="1"          # 常规实验默认用 Neo4j 挖掘窗口
```

常见取值：

| 变量                            | 默认     | 说明                                                               |
| ------------------------------- | -------- | ------------------------------------------------------------------ |
| `DLD_OCR_PROVIDER`            | `none` | `none` 不读字；当前常用 `paddleocr`；`rapidocr` 可做备用对照 |
| `DLD_OCR_USE_CUDA`            | `0`    | PaddleOCR / RapidOCR 的统一 CUDA 开关                              |
| `DLD_RAPIDOCR_USE_CUDA`       | `0`    | RapidOCR 兼容开关；只在切到 `rapidocr` 时需要关心                |
| `DLD_OCR_WORKERS`             | `1`    | OCR 并发 worker 数；每个 worker 会有自己的 OCR 引擎                |
| `DLD_OCR_MAX_IMAGE_SIDE`      | `1280` | OCR 前最长边缩放上限                                               |
| `DLD_FRAME_PROBE_MULTIPLIER`  | `6`    | 每个窗口最多 probe 数约为 `max_keyframes * multiplier`           |
| `DLD_FRAME_SEQUENTIAL_GAP_MS` | `5000` | 相邻时间点在多少毫秒内用顺序解码                                   |

### Neo4j

```powershell
.\tools\start_neo4j.ps1

$env:DLD_NEO4J_URI="bolt://localhost:7687"
$env:DLD_NEO4J_USER="neo4j"
$env:DLD_NEO4J_PASSWORD="data-leak-detector"
$env:DLD_NEO4J_DATABASE="neo4j"
$env:DLD_NEO4J_LOG_MINER="1"
$env:DLD_NEO4J_REUSE_IMPORT="1"
```

| 变量                               | 默认     | 说明                                                                  |
| ---------------------------------- | -------- | --------------------------------------------------------------------- |
| `DLD_NEO4J_LOG_MINER`            | `0`    | 环境变量方式打开 Neo4j log miner；命令行 `--neo4j-log-miner` 更直观 |
| `DLD_NEO4J_LOG_MINER_STRICT`     | `0`    | Neo4j log miner 失败时是否直接失败                                    |
| `DLD_NEO4J_REUSE_IMPORT`         | `1`    | 相同 case/log fingerprint 时复用导入结果                              |
| `DLD_NEO4J_LOG_MINER_BATCH_SIZE` | `2000` | 日志图批量导入大小                                                    |

## 5. VLM-only 评估

当你想测 VLM 准确性，不希望 OCR/log 确定性规则帮忙时，用 `--no-non-vlm`：

```powershell
$python = ".\.venv\Scripts\python.exe"
$env:DLD_OCR_PROVIDER="paddleocr"
$env:DLD_OCR_USE_CUDA="1"
$env:DLD_OCR_WORKERS="1"
$env:DLD_OCR_MAX_IMAGE_SIDE="1280"
$env:DLD_NEO4J_LOG_MINER="1"

& $python main/run_e2e.py `
  --case "spec\data\nas_samples\stage1\2-ai-gpt cherystudio-2" `
  --output-dir "artifacts\vlm_only_check" `
  --neo4j-log-miner `
  --vision `
  --vision-mode hybrid `
  --max-vlm-frames 8 `
  --no-non-vlm
```

这个模式下：

```text
OCR 仍会运行，并用于选 VLM 候选帧；
keyframes_ocr_selected/ 是准备送给 VLM 的帧；
vlm_request.json 记录最终请求里的帧、OCR 文本、prompt 和敏感源别名；
只有 source="vlm" 的观察进入 EventCorrelator；
OCR-only、log-only、lineage-only 的确定性证据不会生成最终 leak path。
```

所以 VLM-only 不是“不开 OCR”，而是“OCR 只辅助筛帧，不作为最终关联证据”。如果 `vlm_frames=0`，说明没有帧被送给 VLM；先看 `ocr_results.json`、`keyframes_ocr_selected/` 和 `vlm_request.json` 是否存在。

三种 VLM 候选帧策略：

| 策略                 | OCR 是否运行 | VLM 看哪些帧                                                         | 用途                                        |
| -------------------- | -----------: | -------------------------------------------------------------------- | ------------------------------------------- |
| `direct_keyframes` |           否 | 非均匀抽帧后的关键帧                                                 | 看“不经过 OCR，关键帧直接 VLM”的效果      |
| `ocr_all`          |           是 | OCR 后保留下来的代表帧，尽量都送 VLM，仍受 `--max-vlm-frames` 限制 | 看“经过 OCR 筛帧，但不提前跳过 VLM”的效果 |
| `ocr_triage`       |           是 | OCR 判为风险、低置信、强日志锚点且 OCR 为空的帧                      | 看“部分提前判定不走 VLM”的效果；默认      |

合帧时加 `--vlm-grid-size 2` 或 `--vlm-grid-size 3`。grid 会按屏幕帧的典型宽高比紧凑排列，最后一组不足 N×N 时不会补空白格。`--max-vlm-frames` 仍表示最多选多少张原始候选帧；合帧后实际请求图片数记录在 `vision.vlm_frames`，原始候选帧数记录在 `vision.vlm_source_frames`。模型实际看到的合帧图会写到 `keyframes_vlm_grid/`，`vlm_request.json` 里保留 grid cell 到原始 `frame_id` 的映射。

需要加速 VLM 调用时加 `--vlm-workers 2` 或设置 `$env:DLD_VLM_WORKERS="2"`。它只把同一轮已选 VLM 帧拆批并发请求，不改变输出目录维度；统计里会记录 `vision.vlm_workers`、`vision.vlm_batches`、`vision.timing_seconds.vlm` 和模型返回的 `vision.vlm_usage`。

示例：

```powershell
& $python main/run_e2e.py `
  --case "spec\data\nas_samples\stage5\U1-StegoImage-1" `
  --output-dir "artifacts\compare_vlm_direct_keyframes" `
  --neo4j-log-miner `
  --vision `
  --vision-mode hybrid `
  --max-vlm-frames 8 `
  --vlm-frame-strategy direct_keyframes `
  --vlm-grid-size 2 `
  --no-non-vlm

& $python main/run_e2e.py `
  --case "spec\data\nas_samples\stage5\U1-StegoImage-1" `
  --output-dir "artifacts\compare_vlm_ocr_all" `
  --neo4j-log-miner `
  --vision `
  --vision-mode hybrid `
  --max-vlm-frames 8 `
  --vlm-frame-strategy ocr_all `
  --vlm-grid-size 2 `
  --no-non-vlm

& $python main/run_e2e.py `
  --case "spec\data\nas_samples\stage5\U1-StegoImage-1" `
  --output-dir "artifacts\compare_vlm_ocr_triage" `
  --neo4j-log-miner `
  --vision `
  --vision-mode hybrid `
  --max-vlm-frames 8 `
  --vlm-frame-strategy ocr_triage `
  --vlm-grid-size 2 `
  --no-non-vlm
```

只检查 VLM 输入、不花模型调用费用时：


## 12. 跑完后看什么

主报告：

```text
artifacts\<output-dir>\<report_id>.json
```

细节目录：

```text
artifacts\<output-dir>\<report_id>\
```

常看文件：

| 文件/目录                         | 看什么                                              |
| --------------------------------- | --------------------------------------------------- |
| `keyframes_raw_all/`            | 抽帧曾经抓到的所有候选帧                            |
| `keyframes_raw/`                | 最终关键帧                                          |
| `keyframe_duplicates.json`      | 去重原因                                            |
| `ocr_results.json`              | OCR 文本、confidence、provider                      |
| `keyframes_ocr_selected/`       | 送给 VLM 的帧                                       |
| `keyframes_vlm_grid/`           | `--vlm-grid-size > 1` 时模型实际收到的合帧图      |
| `frame_observations.json`       | OCR/VLM/log anchored 观察                           |
| `event_correlator_details.json` | correlated events、upload candidates、Datalog facts |
| `leak_paths.json`               | 最终推理路径                                        |

常用判断顺序：

1. `log_miner.source` 是 `in_memory`、`neo4j` 还是 `in_memory_fallback`。
2. `frame_analyzer.statistics.vision.analysis_windows` 是否大于 0。
3. `keyframes_raw/` 是否覆盖关键画面。
4. `ocr_results.json` 是否读到文件名和外发词。
5. `frame_analyzer.statistics.vision.timing_seconds.vlm` 记录 VLM 调用实际耗时。
6. `frame_analyzer.statistics.vision.vlm_usage` 记录模型响应返回的真实 token usage；如果 provider 没返回 usage，这里为空。
7. `frame_analyzer.statistics.vision.vlm_request_metrics` 记录本次请求的图片数、像素数、prompt 字符数等可核验指标。
8. `event_correlator_details.json` 里是否有 `join_reasons`。
9. `leak_paths.json` 是否有 `full_path`。

## 13. 常见问题

### OCR provider 是 `paddleocr_missing`

说明当前配置选了 `paddleocr`，但当前 Python 环境没有装。先确认用了 `.venv`：

```powershell
$python = ".\.venv\Scripts\python.exe"
& $python -c "import paddleocr; print('paddleocr ok')"
```

如果只是临时想做 OCR 对照，可以切到 RapidOCR：

```powershell
$env:DLD_OCR_PROVIDER="rapidocr"
$env:DLD_OCR_USE_CUDA="1"
```

再重跑。当前进程环境变量会覆盖 `.env`。

### `vlm_frames=0`

说明没有帧被选中送 VLM。先看：

```text
ocr_results.json
keyframes_ocr_selected/
frame_analyzer.statistics.vision.ocr_frames
```

如果 OCR 文本为空，VLM 候选可能选不出来。

### 非 VLM 和 VLM 结果混在一起看不清

分别跑三个输出目录：

```text
artifacts\compare_ocr_only
artifacts\compare_vlm_only
artifacts\compare_hybrid
```

并固定同一个 case、同一套 OCR 配置。

### Neo4j 一直 fallback

先确认服务启动：

```powershell
.\tools\start_neo4j.ps1
```

再看报告里的 `log_miner.fallback_reason`。常规实验建议保持 Neo4j 可用并显式加 `--neo4j-log-miner`；只有临时快速跑、不关心图挖掘窗口时，再设置 `$env:DLD_NEO4J_LOG_MINER="0"`。
