# 运行命令

本文放平常调试 DataLeakDetector 最常用的命令。默认工作目录是仓库根目录：

```powershell
cd D:\Projects\Job\DataLeakDetector
```

## 1. 参数速查

| 参数 | 作用 | 常用场景 |
|---|---|---|
| `--case` / `-c` | 指定 `spec/data` 样例目录，自动发现日志、视频、groundtruth 和敏感源 | 跑真实样例时优先用这个 |
| `--log` / `-l` | 直接指定 JSON/JSONL 日志文件 | 跑自定义日志或临时最小样例 |
| `--video` / `-v` | 直接指定视频文件 | 配合 `--log` 使用 |
| `--groundtruth` | 指定 groundtruth 文件 | 配合 `--log` 使用时补评估口径 |
| `--output-dir` / `-o` | 输出报告和 artifact 的根目录 | 建议每轮实验单独一个目录 |
| `--sensitive-file` | 手工指定敏感源文件，可重复 | 没有 groundtruth 或想额外指定敏感源 |
| `--observations` | 读取预先生成的 frame observations JSON | 跳过视觉模型，复用已有观察 |
| `--vision` | 打开抽帧、OCR/VLM 视觉链路 | 需要视频证据时使用 |
| `--vision-mode ocr` | 只跑 OCR，不调用 VLM | 非 VLM baseline、OCR 调参 |
| `--vision-mode hybrid` | OCR 后选择部分帧送 VLM | 正常视觉增强检测 |
| `--vision-mode vlm` | 允许 VLM 路径 | VLM 实验；仍依赖抽帧和候选帧选择 |
| `--max-vlm-frames 0` | 不发送任何帧给 VLM | 确保 OCR-only / 非 VLM |
| `--max-vlm-frames N` | 最多发送 N 张 OCR 候选帧给 VLM | 控制费用和速度 |
| `--no-non-vlm` | 关闭确定性 OCR/log 证据，只让 VLM 观察进入关联推理 | 单独评估 VLM 准确性 |
| `--neo4j-log-miner` | 用 Neo4j 做日志挖掘/抽帧窗口 | 长日志、固定样例复跑 |
| `--no-reuse-neo4j-import` | 禁止复用 Neo4j 日志导入 | 调 importer 或 schema 时使用 |
| `--neo4j` | 把最终报告写入 Neo4j 图 | 需要图查询/可视化报告时使用 |
| `--neo4j-strict` | Neo4j 写入失败时直接失败 | CI 或确认 Neo4j 必须可用时使用 |

注意：进程环境变量优先级高于 `.env`。也就是说，当前 PowerShell 里设置的 `$env:DLD_OCR_PROVIDER="rapidocr"` 会覆盖 `.env` 里的同名配置。

## 2. 常用环境变量

### OCR / 抽帧

```powershell
$env:DLD_OCR_PROVIDER="rapidocr"      # none / tesseract / rapidocr / paddleocr
$env:DLD_RAPIDOCR_USE_CUDA="1"       # RapidOCR 尝试 CUDA；失败时看 ocr_results.json provider
$env:DLD_OCR_WORKERS="2"             # RTX 4060 Laptop GPU 先试 2
$env:DLD_OCR_MAX_IMAGE_SIDE="960"    # 降低 OCR 输入边长，节省显存/时间
```

常见取值：

| 变量 | 默认 | 说明 |
|---|---|---|
| `DLD_OCR_PROVIDER` | `none` | `none` 不读字；`rapidocr` 适合中文 Windows UI；`paddleocr` 需要安装 paddleocr |
| `DLD_RAPIDOCR_USE_CUDA` | `0` | RapidOCR 是否尝试 CUDA |
| `DLD_OCR_WORKERS` | `1` | OCR 并发 worker 数；每个 worker 会有自己的 OCR 引擎 |
| `DLD_OCR_MAX_IMAGE_SIDE` | `1280` | OCR 前最长边缩放上限 |
| `DLD_FRAME_PROBE_MULTIPLIER` | `6` | 每个窗口最多 probe 数约为 `max_keyframes * multiplier` |
| `DLD_FRAME_SEQUENTIAL_GAP_MS` | `5000` | 相邻时间点在多少毫秒内用顺序解码 |

### Neo4j

```powershell
$env:DLD_NEO4J_URI="bolt://localhost:7687"
$env:DLD_NEO4J_USER="neo4j"
$env:DLD_NEO4J_PASSWORD="data-leak-detector"
$env:DLD_NEO4J_DATABASE="neo4j"
$env:DLD_NEO4J_REUSE_IMPORT="1"
```

| 变量 | 默认 | 说明 |
|---|---|---|
| `DLD_NEO4J_LOG_MINER` | `0` | 环境变量方式打开 Neo4j log miner；命令行 `--neo4j-log-miner` 更直观 |
| `DLD_NEO4J_LOG_MINER_STRICT` | `0` | Neo4j log miner 失败时是否直接失败 |
| `DLD_NEO4J_REUSE_IMPORT` | `1` | 相同 case/log fingerprint 时复用导入结果 |
| `DLD_NEO4J_LOG_MINER_BATCH_SIZE` | `2000` | 日志图批量导入大小 |

## 3. 快速健康检查

不跑视觉，只确认样例发现、日志归一化、关联和推理能跑通：

```powershell
python tools\smoke_pipeline.py `
  --case "spec\data\nas_samples\stage1\0-normal-ai-chatgpt-1"
```

写出报告：

```powershell
python tools\smoke_pipeline.py `
  --case "spec\data\nas_samples\stage1\0-normal-ai-chatgpt-1" `
  --output-dir "artifacts\smoke"
```

## 4. OCR-only / 非 VLM baseline

这是看“不借助 VLM，日志 + OCR + Datalog 能不能判”的常用命令：

```powershell
$env:DLD_OCR_PROVIDER="rapidocr"
$env:DLD_RAPIDOCR_USE_CUDA="1"
$env:DLD_OCR_WORKERS="2"
$env:DLD_OCR_MAX_IMAGE_SIDE="960"

python main/run_e2e.py `
  --case "spec\data\nas_samples\stage1\2-ai-gpt cherystudio-2" `
  --output-dir "artifacts\non_vlm_check" `
  --vision `
  --vision-mode ocr `
  --max-vlm-frames 0
```

跑完重点看：

```text
artifacts\non_vlm_check\<report_id>\ocr_results.json
artifacts\non_vlm_check\<report_id>\frame_observations.json
artifacts\non_vlm_check\<report_id>\event_correlator_details.json
artifacts\non_vlm_check\<report_id>\leak_paths.json
```

关键字段：

```text
frame_analyzer.statistics.vision.vlm_frames == 0
event_correlator.statistics.non_vlm_enabled == true
leak_reasoner.leak_path_count
```

## 5. VLM-only 评估

当你想测 VLM 准确性，不希望 OCR/log 确定性规则帮忙时，用 `--no-non-vlm`：

```powershell
$env:DLD_OCR_PROVIDER="rapidocr"
$env:DLD_RAPIDOCR_USE_CUDA="1"
$env:DLD_OCR_WORKERS="2"
$env:DLD_OCR_MAX_IMAGE_SIDE="960"

python main/run_e2e.py `
  --case "spec\data\nas_samples\stage1\2-ai-gpt cherystudio-2" `
  --output-dir "artifacts\vlm_only_check" `
  --vision `
  --vision-mode hybrid `
  --max-vlm-frames 8 `
  --no-non-vlm
```

这个模式下：

```text
OCR 仍用于选 VLM 候选帧；
只有 source="vlm" 的观察进入 EventCorrelator；
OCR-only、log-only、lineage-only 的确定性证据不会生成最终 leak path。
```

如果 `vlm_frames=0`，说明没有帧被送给 VLM；先看 `ocr_results.json` 和 `keyframes_ocr_selected/`。

## 6. 混合模式

正常想要最强召回时，用 OCR + VLM + 非 VLM 规则一起跑：

```powershell
$env:DLD_OCR_PROVIDER="rapidocr"
$env:DLD_RAPIDOCR_USE_CUDA="1"
$env:DLD_OCR_WORKERS="2"
$env:DLD_OCR_MAX_IMAGE_SIDE="960"

python main/run_e2e.py `
  --case "spec\data\nas_samples\stage1\2-ai-gpt cherystudio-2" `
  --output-dir "artifacts\hybrid_check" `
  --vision `
  --vision-mode hybrid `
  --max-vlm-frames 8
```

对比实验建议固定同一个 case，分别跑：

```text
OCR-only 非 VLM:  --vision --vision-mode ocr --max-vlm-frames 0
VLM-only:         --vision --vision-mode hybrid --max-vlm-frames 8 --no-non-vlm
Hybrid:           --vision --vision-mode hybrid --max-vlm-frames 8
```

## 7. 只看抽帧效果

如果只想看抽帧是否覆盖关键画面，可以先不关心 VLM：

```powershell
$env:DLD_OCR_PROVIDER="none"

python main/run_e2e.py `
  --case "spec\data\nas_samples\stage1\1-email-gmail-1" `
  --output-dir "artifacts\frame_selection_check" `
  --vision `
  --vision-mode ocr `
  --max-vlm-frames 0
```

重点看：

```text
keyframes_raw_all/         # 全局去重前候选帧
keyframes_raw/             # 最终关键帧
keyframe_duplicates.json   # 被去重的帧和原因
```

如果 `keyframes_raw_all/` 都没有目标画面，优先查日志窗口；如果 raw_all 有、raw 没有，看 `keyframe_duplicates.json`。

## 8. Neo4j log miner

### 启动本地 Neo4j

```powershell
.\tools\start_neo4j.ps1
```

### 只用 Neo4j 做日志挖掘/抽帧窗口，不写最终报告图

```powershell
python main/run_e2e.py `
  --case "spec\data\nas_samples\stage1\2-ai-Gemini-2" `
  --output-dir "artifacts\neo4j_frame_selection_check" `
  --neo4j-log-miner `
  --vision `
  --vision-mode ocr `
  --max-vlm-frames 0
```

看主报告：

```json
"log_miner": {
  "source": "neo4j"
}
```

如果是：

```json
"source": "in_memory_fallback"
```

说明 Neo4j 连接或查询失败了，非 strict 模式自动回退到 InMemory。

### 同时测试 Neo4j log miner 和最终报告图写入

```powershell
python main/run_e2e.py `
  --case "spec\data\nas_samples\stage1\1-email-fastmail-1" `
  --output-dir "artifacts\neo4j_full_check" `
  --neo4j-log-miner `
  --neo4j `
  --vision `
  --vision-mode ocr `
  --max-vlm-frames 0
```

### strict：失败就报错，不 fallback

```powershell
$env:DLD_NEO4J_LOG_MINER_STRICT="1"

python main/run_e2e.py `
  --case "spec\data\nas_samples\stage1\1-email-fastmail-1" `
  --output-dir "artifacts\neo4j_strict_check" `
  --neo4j-log-miner `
  --neo4j `
  --neo4j-strict `
  --vision `
  --vision-mode ocr `
  --max-vlm-frames 0
```

### 强制重新导入日志图

```powershell
python main/run_e2e.py `
  --case "spec\data\nas_samples\stage1\1-email-fastmail-1" `
  --output-dir "artifacts\neo4j_reimport_check" `
  --neo4j-log-miner `
  --no-reuse-neo4j-import `
  --vision `
  --vision-mode ocr `
  --max-vlm-frames 0
```

### 停止本地 Neo4j

```powershell
.\tools\stop_neo4j.ps1
```

## 12. 跑完后看什么

主报告：

```text
artifacts\<output-dir>\<report_id>.json
```

细节目录：

```text
artifacts\<output-dir>\<report_id>\
```

常看文件：

| 文件/目录 | 看什么 |
|---|---|
| `keyframes_raw_all/` | 抽帧曾经抓到的所有候选帧 |
| `keyframes_raw/` | 最终关键帧 |
| `keyframe_duplicates.json` | 去重原因 |
| `ocr_results.json` | OCR 文本、confidence、provider |
| `keyframes_ocr_selected/` | 送给 VLM 的帧 |
| `frame_observations.json` | OCR/VLM/log anchored 观察 |
| `event_correlator_details.json` | correlated events、upload candidates、Datalog facts |
| `leak_paths.json` | 最终推理路径 |

常用判断顺序：

1. `log_miner.source` 是 `in_memory`、`neo4j` 还是 `in_memory_fallback`。
2. `frame_analyzer.statistics.vision.analysis_windows` 是否大于 0。
3. `keyframes_raw/` 是否覆盖关键画面。
4. `ocr_results.json` 是否读到文件名和外发词。
5. `event_correlator_details.json` 里是否有 `join_reasons`。
6. `leak_paths.json` 是否有 `full_path`。

## 13. 常见问题

### OCR provider 是 `paddleocr_missing`

说明当前配置选了 `paddleocr`，但环境没装。切到 RapidOCR：

```powershell
$env:DLD_OCR_PROVIDER="rapidocr"
```

再重跑。当前进程环境变量会覆盖 `.env`。

### `vlm_frames=0`

说明没有帧被选中送 VLM。先看：

```text
ocr_results.json
keyframes_ocr_selected/
frame_analyzer.statistics.vision.ocr_frames
```

如果 OCR 文本为空，VLM 候选可能选不出来。

### 非 VLM 和 VLM 结果混在一起看不清

分别跑三个输出目录：

```text
artifacts\compare_ocr_only
artifacts\compare_vlm_only
artifacts\compare_hybrid
```

并固定同一个 case、同一套 OCR 配置。

### Neo4j 一直 fallback

先确认服务启动：

```powershell
.\tools\start_neo4j.ps1
```

再看报告里的 `log_miner.fallback_reason`。如果只是想调抽帧，不需要强制 Neo4j；`in_memory` 路径已经够用。
