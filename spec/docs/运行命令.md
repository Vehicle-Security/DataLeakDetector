查看指定样例的抽帧结果

```
$env:DLD_OCR_PROVIDER="rapidocr"
$env:DLD_RAPIDOCR_USE_CUDA="1"
$env:DLD_OCR_WORKERS="2"
$env:DLD_OCR_MAX_IMAGE_SIDE="960"

python main/run_e2e.py `
  --case "spec\data\nas_samples\stage5\Bluetooth-SensitiveLeak" `
  --output-dir "artifacts\frame_selection_gpu_check" `
  --vision `
  --vision-mode ocr `
  --max-vlm-frames 0
```

有一点变化，主要是加 `--neo4j-log-miner`。

**只用 Neo4j 做日志挖掘/抽帧窗口，不写最终报告图：**

```powershell
python main/run_e2e.py `
  --case "spec\data\nas_samples\stage5\Bluetooth-SensitiveLeak" `
  --output-dir "artifacts\neo4j_frame_selection_check" `
  --neo4j-log-miner `
  --vision `
  --vision-mode ocr `
  --max-vlm-frames 0
```

**同时测试 Neo4j log miner 和最终报告写入 Neo4j：**

```powershell
python main/run_e2e.py `
  --case "spec\data\nas_samples\stage1\1-email-fastmail-1" `
  --output-dir "artifacts\neo4j_frame_selection_check" `
  --neo4j-log-miner `
  --neo4j `
  --vision `
  --vision-mode ocr `
  --max-vlm-frames 0
```

如果想失败就直接报错，而不是 fallback：

```powershell
$env:DLD_NEO4J_LOG_MINER_STRICT="1"

python main/run_e2e.py `
  --case "spec\data\nas_samples\stage1\1-email-fastmail-1" `
  --output-dir "artifacts\neo4j_frame_selection_check" `
  --neo4j-log-miner `
  --neo4j `
  --neo4j-strict `
  --vision `
  --vision-mode ocr `
  --max-vlm-frames 0
```

跑完看主报告里的：

```json
"log_miner": {
  "source": "neo4j"
}
```

如果还是 `"source": "in_memory_fallback"`，说明 Neo4j 连接或查询失败了。
