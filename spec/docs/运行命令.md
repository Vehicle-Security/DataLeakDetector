# 运行命令

所有命令都在仓库根目录执行：

```powershell
cd D:\Projects\Job\DataLeakDetector
python --version
```

当前视觉链路只有一种策略：`direct keyframes`。流程是日志挖掘可疑窗口、按画面变化抽关键帧、把关键帧直接交给 VLM、再进入事件关联和 Datalog 推理。没有 OCR、ROI、OCR triage、release matrix，也不需要 `.venv`。

## 1. 环境准备

安装项目和测试依赖：

```powershell
python -m pip install -e ".[dev,vision]"
python -c "import cv2, neo4j, pytest; print('runtime ok')"
```

VLM 使用 OpenAI-compatible 接口。按需在 `.env` 或当前 PowerShell 里配置：

```powershell
$env:DLD_VLM_USE_CODING_PLAN = "1"
$env:DLD_VLM_CODING_BASE_URL = "https://coding.dashscope.aliyuncs.com/v1"
$env:DLD_VLM_CODING_API_KEY = "<your-key>"
```

常用并发：

```powershell
$env:DLD_VLM_WORKERS = "4"
$env:DLD_VLM_FAST_DISPATCH = "1"
```

Neo4j 只作为可选日志挖掘后端，不写回检测报告图。默认不配置 Neo4j，流水线直接使用内存日志挖掘。临时启用 Neo4j 日志挖掘：

```powershell
python main/run_e2e.py `
  --case "spec\data\nas_samples\stage1\1-email-fastmail-1" `
  --output-dir "artifacts\debug_neo4j_log_miner" `
  --vision `
  --neo4j-log-miner
```

也可以写到本地 `.env`：

```powershell
DLD_NEO4J_LOG_MINER=1
DLD_NEO4J_URI=bolt://localhost:7687
DLD_NEO4J_USER=neo4j
DLD_NEO4J_PASSWORD=data-leak-detector
DLD_NEO4J_DATABASE=neo4j
```

## 2. 快速自检

不调用真实模型，只检查日志挖掘、抽帧、VLM 请求构造和报告输出是否跑通：

```powershell
$env:DLD_VLM_DRY_RUN = "1"
python main/run_e2e.py `
  --case "spec\data\nas_samples\stage1\1-email-fastmail-1" `
  --output-dir "artifacts\smoke_direct_only" `
  --vision `
  --max-vlm-frames 2 `
  --vlm-workers 1
Remove-Item Env:\DLD_VLM_DRY_RUN
```

重点产物：

```text
artifacts\smoke_direct_only\<report_id>\keyframes_raw\
artifacts\smoke_direct_only\<report_id>\keyframes_vlm_input\
artifacts\smoke_direct_only\<report_id>\vlm_request.json
artifacts\smoke_direct_only\<report_id>\vlm_response.json
artifacts\smoke_direct_only\<report_id>\leak_paths.json
```

## 3. Debug 单样本

Debug 模式会在每个样本目录下保留 VLM 输入、请求和返回，适合定位漏判/误判：

```powershell
python main/run_e2e.py `
  --case "spec\data\nas_samples\stage1\1-email-fastmail-1" `
  --output-dir "artifacts\debug_single" `
  --vision `
  --max-vlm-frames -1 `
  --vlm-grid-layout 4x1 `
  --vlm-workers 4 `
  --vlm-fast-dispatch
```

## 4. Release 全量

Release 模式默认启用 direct keyframes、继承父目录 groundtruth，并关闭非 VLM 证据合并。需要 LLM 判例复核时，VLM 阶段应加 `--release-debug-artifacts`，以保留 Judge 所需的每例结构化证据。

预处理只抽 keyframes，不调用 VLM：

```powershell
$runDir = "artifacts\full_release_grid4x1_judged1"
New-Item -ItemType Directory -Force $runDir | Out-Null
python main/run_e2e.py `
  --case-root "spec\data\nas_samples" `
  --case-workers 2 `
  --release `
  --release-precompute-only `
  --output-dir $runDir `
  *> "$runDir\precompute.log"
```

VLM 阶段：

```powershell
$runDir = "artifacts\full_release_grid4x1_judged"
$env:DLD_VLM_RETRY_ATTEMPTS = "6"
$env:DLD_VLM_RETRY_BACKOFF_SECONDS = "2"
python main/run_e2e.py `
  --case-root "spec\data\nas_samples" `
  --case-workers 4 `
  --release `
  --release-debug-artifacts `
  --output-dir $runDir `
  --vlm-grid-layout 4x1 `
  --vlm-workers 4 `
  --vlm-fast-dispatch `
  *> "$runDir\vlm.log"
```

Release 汇总文件：

```text
artifacts\full_release_direct\release_report.json
artifacts\full_release_direct\release_comparison.json
artifacts\full_release_direct\release_progress.json
artifacts\full_release_direct\release_precompute_progress.json
```

## 5. Release 错例定向重跑

复用全量运行的 `vision_precompute`，只运行清单中的案例。该命令适合 VLM 限流或错例复核；新的汇总输出不会覆盖原全量报告。
`--vlm-grid-layout 4x1` 只改变发送给 VLM 的拼图方式，不会重新抽取关键帧。
`--release-debug-artifacts` 会在 `$runDir\case_debug` 下保留每例 VLM 请求、原始响应和解析结果，便于定位 API 失败或模型漏判。

```powershell
$sourceRun = "artifacts\full_release_direct_20260712_051122"
$runDir = "artifacts\rerun_grid4x1_debug_70"
New-Item -ItemType Directory -Force $runDir | Out-Null
$env:DLD_VLM_RETRY_ATTEMPTS = "6"
$env:DLD_VLM_RETRY_BACKOFF_SECONDS = "2"
python main/run_e2e.py `
  --case-root "spec\data\nas_samples" `
  --case-list "$sourceRun\grid2_rerun_case_ids.txt" `
  --release `
  --release-debug-artifacts `
  --output-dir $runDir `
  --vision-precompute-root "$sourceRun\vision_precompute" `
  --case-workers 1 `
  --vlm-workers 1 `
  --vlm-grid-layout 4x1 `
  *> "$runDir\vlm.log"
```

## 7. LLM 判例复核

在带 `--release-debug-artifacts` 的完整重跑结束后，可对原始评测不一致的 case 做独立判例复核。
该步骤不会修改 groundtruth、检测结果或原始 Release 汇总；它只生成单独的裁决文件。
复核会向配置的外部 LLM 发送 groundtruth、VLM 结构化事件和关联链摘要，不发送原视频或原始日志。

```powershell
$runDir = "artifacts\rerun_grid4x1_debug_70_fixed"
$env:DLD_JUDGE_API_KEY = "<在当前 PowerShell 会话中设置密钥>"

python tools\adjudicate_release.py `
  --release-report "$runDir\release_report.json" `
  --case-debug-root "$runDir\case_debug" `
  --output "$runDir\llm_adjudication.json" `
  --base-url "https://api.deepseek.com" `
  --model "deepseek-v4-pro"
```

如需在 Release 运行期间立即复核每个已完成错例，可在另一个 PowerShell 窗口运行：

```powershell
$runDir = "artifacts\rerun_grid4x1_debug_70_fixed"
$env:DLD_JUDGE_API_KEY = "<在当前 PowerShell 会话中设置密钥>"

python tools\watch_release_adjudication.py `
  --release-progress "$runDir\release_progress.json" `
  --case-debug-root "$runDir\case_debug" `
  --output "$runDir\llm_adjudication_live.json" `
  --base-url "https://api.deepseek.com" `
  --model "deepseek-v4-pro"
```
