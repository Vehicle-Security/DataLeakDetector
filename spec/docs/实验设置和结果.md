## 实验2：泄露判定和路径还原能力

### Table 3：整体案例级泄露检测

table3：测试 ScreenGuard 对正常办公样本和泄露样本的整体区分能力，并与其他 baseline 对比。

VLM baseline 统一协议：每个 logical case 向模型发送全部原始 MP4 录屏、对应的原始 `keyevents.json` 文件内容，以及该 Stage 对应的原始 `spec/config/sensitive_files_<stage>.json` 敏感文件清单；不使用本地关键帧、日志窗口、ScreenGuard 的证据关联或规则推理。敏感源身份与项目一致：规范化大小写、引号和路径分隔符后优先全路径匹配，并以相同扩展名的文件名（忽略扩展名前的意外空格）兜底；目录差异不单独否定同一来源。案例判定与项目的风险口径一致：敏感源/派生载体与外部能力应用的文件选择、资源身份、上传发送、粘贴剪贴板或屏幕共享等存在证据关联即可为 positive，完成的 send/upload 是强证据但非必要条件。模型必须返回固定 JSON，包含 `verdict`、`events` 和 `paths`；每条 `path` 记录 `source_file`、按顺序排列的 `steps`、以及最终 `sink`。同一份原始输出用于 Table 3 的案例判定和 Table 4 的链路评分。

### Table 4：多步外发链路还原

table4：测试 ScreenGuard 对多步外发案例的链路还原能力，并与可输出链路的 baseline 对比。

对 VLM baseline，按固定 JSON 中的 `paths` 评分：`source_file -> steps[] -> sink`。`steps` 中每项显式给出操作类别、输入/输出载体、carrier、时间和证据；`sink` 显式给出 channel、application、destination、时间和证据。格式错误或缺少可判定字段的响应保留在实验制品中，不作为成功路径补全。

- 可计算指标：Full Path Acc\.、Step Rec\. 、Sink Acc\.。
- 其中 Full Path Acc\. 按项目 `LeakPath` 口径评分：只需语义上建立“敏感源（或可回溯派生载体）→ 最终外发渠道”的连通链，传播步骤可以为零个或多个；不要求逐项复现中间文件、绝对路径或内部渠道标签。敏感文件清单缺失 / 路径不一致造成的源文件差异，以及虚拟机内未落盘的中间载体，不作为失败。Step Rec\. 按 `case_debug` 人工逐步骤清单统计语义传播和外发步骤还原率（known `65` 步、unseen `26` 步）；Sink Acc\. 统计最终外发目的地的语义识别正确率。
- 数据集样本：完整外发案例30个，未知案例15个。
- known 的 Full ScreenGuard 数值为本轮新跑 Full 与 `spec/case_debug` 复核结果的对应指标算术均值。unseen 另纳入一轮 Stage5 复核结果，写为三轮均值；存在波动的指标以“均值（上界 / 下界）”表示，单位为百分点（pp）。

> 单次评测保留其原始 n/N 记录；known 使用两轮均值，unseen 使用三轮均值。仅存在轮次波动的 unseen 指标显示上/下界。旧制品中由 `tools/evaluate_table5.py` 生成的 Step Rec. `48/20` 只覆盖 `unknown_risk` 标注项，不是本表采用的逐步骤口径，因而不再填入表格。
>
> 这个表主要证明：ScreenGuard 不只是能判断案例是否泄露，还能否还原敏感数据从原始文件到中间载体再到最终外发目的地的传播过程。

### figure6 不同 Stage 的本地关键帧筛选效果

> 在不同类型的泄露场景中，ScreenGuard 的全局视觉去重能够将日志窗口产生的候选关键帧减少多少？

实现边界：

- `raw_all` 是各日志分析窗口经动作状态抽帧和视觉变化抽帧后产生的全部候选帧。
- `raw` 是 `raw_all` 经跨窗口全局视觉去重后保留的关键帧。当前不使用 OCR 进行帧筛选或文本语义去重。
- `VLM grid` 是将 `raw` 按 4×1 布局打包后实际作为图像输入送入 VLM 的网格图数量。该阶段不丢弃关键帧，而是以一张网格图承载最多四张关键帧，减少多模态请求中的图像数量。
- 项目输入是已录制的 MP4 和终端监控日志，不实现屏幕录制器，因此不统计“每日录屏存储量”。

实验流程：

- 使用 `artifacts/full_release_grid4x1_20260810_010848/vision_precompute` 中 326 个 case 的完整关键帧制品。
- 按 case 路径的顶层 Stage 分组，累加各 session `artifact_manifest.json` 中的 `keyframes_raw_all_files` 和 `keyframes_raw_files`；实际 VLM grid 图数取 Full 运行 `release_report.json` 的 `vision.vlm_frames`。
- 视觉去重数定义为 `raw_all - raw`；网格打包减少的图像数定义为 `raw - VLM grid`；总减少数定义为 `raw_all - VLM grid`。关键帧预计算发生在 VLM 调用之前；网格图数取实际 Full 运行，受 4×1 布局影响。
