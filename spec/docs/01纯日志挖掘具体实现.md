# 纯日志挖掘具体实现

## 1. 适用范围

本文说明未启用 Neo4j 时，DataLeakDetector 如何仅依赖原始日志、维护的敏感源配置和 Python 内存数据结构生成 `AnalysisWindow`。该路径由 `InMemoryLogMiner` 实现，是默认日志挖掘后端。

```text
JSON records -> LogEvent[] -> InMemoryLogMiner
            -> AnalysisWindow[] -> keyframe selector
```

入口 `mine_analysis_windows()` 会读取 Neo4j 配置；当 `DLD_NEO4J_LOG_MINER=0`（默认）或调用方显式关闭该选项时，直接调用：

```python
windows = build_analysis_windows(logs, sensitive_files, vision_config)
return LogMiningResult(
    windows=windows,
    source="in_memory",
    metadata={"status": "ready", "windows": len(windows), "neo4j_enabled": False},
)
```

该过程不连接 Neo4j、不导入图数据，也不改变最终泄露判定；它的输出仅供关键帧选择和 VLM 视觉复核使用。

## 2. 输入规范化

### 2.1 日志记录到 `LogEvent`

流水线先读取 `logs.json` 或 `keyevents.json`，必要时补入传输相关原始事件，再通过 `normalize_logs()` 转为统一的 `LogEvent`。其核心字段如下：

| `LogEvent` 字段 | 来源 | 用途 |
| --- | --- | --- |
| `event_id` | 原始 `event_id` 或顺序编号 | 事件去重、窗口锚点与证据引用 |
| `timestamp_ms` | `timestamp` / `time` | 事件排序和跨 session 时间对齐 |
| `video_time_ms` | 优先 `extra.relative_timestamp`，否则由录制开始时间换算 | 唯一用于抽帧窗口的时间坐标 |
| `event_type` | `event_type` / `type` | 动作识别，如上传、发送、复制、打开或前台切换 |
| `file_path` | 文件路径、目标路径或上传检测字段 | 敏感源匹配和派生文件识别 |
| `process_name` / `app_name` | 进程信息与应用字段 | 前端应用、外接设备和风险通道识别 |
| `window_title` | 窗口信息 | 应用类别、敏感文件标题和外发界面辅助判断 |
| `raw` | 原始日志对象 | 保留采集端扩展字段，例如 `raw_operation`、`source`、`upload_detection` |

时间映射逻辑如下：

```text
if extra.relative_timestamp is valid:
    video_time_ms = relative_timestamp * 1000
elif timestamp_ms and recording_start_ms:
    video_time_ms = max(timestamp_ms - recording_start_ms, 0)
else:
    video_time_ms = -1
```

`video_time_ms < 0` 的事件无法稳定定位视频，因此不会成为抽帧窗口的动作锚点。路径会统一为 `/` 分隔形式；文件比较优先使用完整规范化路径，在安全条件满足时才使用文件名兜底匹配。

### 2.2 敏感源输入

内存挖掘只接收维护的原始敏感文件列表。`_normalize_sensitive_files()` 对路径进行规范化和去重，随后用 `same_file()`、窗口标题和日志文本进行匹配。派生文件不是初始敏感源；它通过复制、导出、压缩、截图或其他日志关系在后续关联阶段回溯到源文件。

## 3. 内存数据流

`build_analysis_windows()` 是内存路径的主函数。其实现可概括为：

```text
ordered = sort(logs where video_time_ms >= 0)
sensitive = normalize_and_dedupe(sensitive_files)

timeline = SensitiveTimeline.from_logs(ordered, sensitive)
clipboard_context = find_sensitive_clipboard_events(ordered, sensitive)

candidates = [event for event in ordered if
    is_foreground_transition(event)
    or may_need_analysis_window(event, sensitive)
    or may_be_derived_file_event(event, sensitive)]
candidates = select_semantic_candidates(candidates, sensitive)

event_view = compact_event_view(ordered, candidates)
action_windows = [
    build_analysis_window_for_event(event, event_view, sensitive, timeline, clipboard_context)
    for event in candidates
]

external_windows = build_outbound_context_windows(ordered, action_windows, sensitive)
windows = remove_actions_already_covered_by_external_session(action_windows, external_windows)
return finalize_windows(windows + external_windows, event_view)
```

这一路径中使用的都是已排序列表、集合、字典和轻量数据类，不依赖外部索引服务。

## 4. 敏感活动与剪贴板上下文

### 4.1 `_SensitiveTimeline`

`_SensitiveTimeline.from_logs()` 针对每个原始敏感源收集相关事件，并从打开事件开始构造敏感活动区间：

```text
for each sensitive source:
    related = events matching this source
    for each open event:
        end = explicit end_time
              or first following close event
              or next open event / session end
        record (source, open_time, end_time, related anchors)
merge contiguous intervals of the same source
```

窗口构造时使用两种查询：

- `active_at(t)`：动作是否发生在敏感文件活动区间中；
- `recent_at(t, radius)`：动作是否发生在最近敏感信号后。普通动作通常使用较短范围；剪贴板和粘贴使用更长范围，以覆盖跨应用操作。

### 4.2 `_sensitive_clipboard_event_ids`

剪贴板事件往往不带准确文件路径。该函数按时间维护“当前文档是否敏感”“最近敏感上下文”和“剪贴板是否被敏感内容污染”等内存状态，并识别后续粘贴或切换到聊天、邮件、浏览器等外部应用的事件。

其关键点是按应用族维护上下文，例如 WPS、Office 等同类应用归并处理；而不是仅因为某个敏感文件在很久以前打开过，就把后续所有剪贴板操作都视为敏感。

## 5. 候选事件筛选

候选初筛保留以下事件：

1. 前台切换、窗口变化、窗口关闭等前端状态事件；
2. 直接命中敏感源，或可被识别为上传、发送、粘贴、剪贴板、采集、共享、外接设备等动作的事件；
3. 可能代表派生文件的创建、修改、重命名、导出或压缩事件。

之后 `_select_semantic_candidates()` 进一步压缩重复或低价值事件，并补全若干关键语义：

| 识别结果 | 作用 |
| --- | --- |
| `upload` / `send` / `file_selected` | 外发动作或文件身份阶段 |
| `clipboard` / `paste` | 跨进程内容传播阶段 |
| `capture_start` / `capture` | 屏幕采集阶段 |
| `screen_share` | 屏幕共享状态 |
| `removable` | 外接设备或蓝牙传输阶段 |
| `derive` | 复制、另存、导出、压缩等派生阶段 |
| `transfer_anchor` | 外部应用访问敏感文档的补充身份锚点 |

`_compact_event_view()` 会保留语义候选、前台切换和动作事件，同时丢弃不影响窗口语义的大量文件系统抖动。后续上下文判断不需要遍历全量原始日志。

## 6. 单事件到 `AnalysisWindow`

`build_analysis_window_for_event()` 负责把候选事件转换为窗口。其判断顺序如下：

```text
if event has no video time:
    discard
if event is system noise and has neither sensitive match nor sensitive clipboard binding:
    discard

action = infer_action(event)
sensitive_context = direct sensitive match
                    or derived-file match
                    or active/recent sensitive timeline
                    or sensitive clipboard binding

if action is external document access to a sensitive source:
    normalize action to file_selected
if action is missing but derived file is detected:
    infer derive or file_selected from frontend-app risk hint
if action is missing but a sensitive clipboard event enters an external app:
    infer paste

priority = strong / weak / none
if priority is none, or weak windows are disabled:
    discard

construct AnalysisWindow(start, end, anchors, action phases, sampling config)
```

强窗口由上传、发送、选文件、粘贴、剪贴板、派生、外接设备、屏幕共享等动作触发。窗口会针对动作调整前后范围：例如导出或压缩需要更长的前置范围以保留源操作；剪贴板和文件选择需要更长的后置范围以保留粘贴、附件或发送状态；邮件附件选择还会延长到可能出现发送按钮或确认结果的后续时段。

生成的 `AnalysisWindow` 具有如下字段：

```json
{
  "start_ms": 115000,
  "end_ms": 150000,
  "reason": "strong:file_selected:log:file_selected",
  "priority": "strong",
  "step_ms": 250,
  "max_keyframes": 18,
  "diff_threshold": 0.015,
  "anchor_ms": [120000],
  "action_anchor_ms": [120000],
  "action_phases": [[120000, "file_selected"]],
  "requires_post_action_state": true,
  "active_apps": ["Outlook"]
}
```

示例中的数值用于说明字段结构；实际范围、采样步长和预算由 `VisionConfig` 控制。

## 7. 外部会话窗口与前台上下文

单独的动作窗口不足以表达完整的外发界面流程，因此 `_build_outbound_context_windows()` 会识别邮件、聊天、AI 对话、网盘、会议、代码托管、社区、协作工具和外接设备等前端会话。

对于每个外部应用会话，函数会：

1. 将相邻前台活动聚合为会话；过长会话按配置分段；
2. 将附近的文件选择、粘贴、剪贴板、采集、派生和发送等动作阶段归属到最合适的会话；
3. 检查会话附近是否有敏感文件访问或敏感上下文；
4. 构造包含 `external_session`、`external_state`、具体动作和 `session_end` 的强窗口；
5. 用会话窗口覆盖已包含的零散动作窗口，避免同一操作被拆成多个视觉证据包。

最后 `_ForegroundTimeline` 根据 `app_switch`、`window_changed` 等事件补充每个窗口的 `active_apps` 与 `active_ranges`。这部分信息会传递给关键帧选择和 VLM 提示词。

## 8. 噪声过滤与回退

`_is_noise_only_event()` 会结合通用规则和 `spec/config/system_noise_profile.json` 过滤系统缓存、浏览器和云盘状态库、后台服务、监控程序窗口及其他环境特定噪声。过滤是保守的：若事件直接命中敏感源或被敏感剪贴板上下文绑定，不能仅因路径像缓存就被静默丢弃。

当没有任何结果型动作窗口时，视觉阶段会调用 `augment_with_video_coverage()` 添加稀疏的视频覆盖窗口。这是视觉兜底，不是日志挖掘将普通事件误判为风险。

## 9. 关键配置参数

| 环境变量 | 默认值 | 内存挖掘中的作用 |
| --- | ---: | --- |
| `DLD_NEO4J_LOG_MINER` | `0` | 关闭时使用本文所述内存路径 |
| `DLD_STRONG_WINDOW_BEFORE_MS` | `5000` | 强动作窗口的基础前置范围 |
| `DLD_STRONG_WINDOW_AFTER_MS` | `15000` | 强动作窗口的基础后置范围 |
| `DLD_FRAME_WINDOW_BEFORE_MS` | `30000` | 弱窗口基础前置范围 |
| `DLD_FRAME_WINDOW_AFTER_MS` | `120000` | 弱窗口基础后置范围 |
| `DLD_STRONG_FRAME_STEP_MS` | `250` | 强窗口后续抽帧的基础时间间隔 |
| `DLD_WEAK_FRAME_STEP_MS` | `2000` | 弱窗口后续抽帧的基础时间间隔 |
| `DLD_MAX_KEYFRAMES_PER_STRONG_WINDOW` | `18` | 强窗口关键帧预算 |
| `DLD_MAX_KEYFRAMES_PER_WEAK_WINDOW` | `2` | 弱窗口关键帧预算 |
| `DLD_INCLUDE_WEAK_WINDOWS` | `0` | 是否保留仅有弱风险线索的窗口 |
| `DLD_EXTERNAL_SESSION_SEGMENT_MS` | `120000` | 将超长外部应用会话拆分为证据包的最大长度 |

这些参数控制窗口和后续抽帧资源分配，不改变 [00口径.md](/media/hwt/Data/Projects/Job/DataLeakDetector/spec/docs/00口径.md) 中的最终泄露判定标准。
