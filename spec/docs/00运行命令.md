# 运行命令

本文按“参数 -> Windows -> Linux/macOS”组织命令。README 只保留项目总览；数据组织、输出解释和故障排查可回看 [README.md](../../README.md)。

## 1. 参数速查

| 参数 | 说明 |
| --- | --- |
| `--case PATH` | 运行一个标准 case 目录，自动发现日志、视频和可选标注 |
| `--log PATH` / `--video PATH` | 直接传入日志，按需附带录屏 |
| `--case-root PATH` | 递归发现根目录下全部 case |
| `--case-list PATH` | 仅运行列表中的相对 case ID；必须配合 `--case-root` |
| `--case-workers N` | 批量或 Release 的 case 并发数 |
| `--release` | 输出一个聚合 Release 报告 |
| `--release-debug-artifacts` | Release 中保留每 case 的 VLM 调试制品 |
| `--release-precompute-only` | 只构建/复用视觉预计算缓存，随后退出 |
| `--vision-precompute-root PATH` | Release 使用已有预计算缓存 |
| `--vision` | 启用日志引导的抽帧和 VLM 分析 |
| `--max-vlm-frames N` | VLM 帧总预算；`0` 不发送帧；负数不设上限 |
| `--vlm-dry-run` | 写出关键帧和 VLM 请求，但不调用模型 |
| `--vlm-grid-size N` / `--vlm-grid-layout RxC` | 网格化 VLM 输入帧 |
| `--vlm-workers N` | VLM 窗口级并发数 |
| `--vlm-max-image-side N` | VLM 图片最长边；`0` 保留原图 |
| `--observations PATH` | 使用预计算的视觉观察 JSON |
| `--no-non-vlm` | 禁用确定性日志证据，仅用于 VLM-only 评测 |
| `--sensitive-files-config PATH` | 指定初始敏感源配置 |
| `--groundtruth PATH` | 直接日志模式下指定仅用于评测的标注 |
| `--neo4j-log-miner` | 启用可选 Neo4j 日志挖掘 |
| `--no-neo4j-log-miner` | 强制使用默认内存日志挖掘 |
| `--no-reuse-neo4j-import` | 强制重新导入 Neo4j 日志 |

当前视觉实现为 `raw_all -> raw` 全局去重后送 VLM；`raw -> VLM frames` 当前只有时间预算采样，没有 OCR、ROI 或语义去重。

## 2. Windows PowerShell

### 2.1 初始化环境

```powershell
Set-Location "D:\Projects\Job\DataLeakDetector"
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev,vision]"
Copy-Item .env.example .env
python tools\vlm_preflight.py
```

### 2.2 单 case Debug

干跑，不调用 VLM：

```powershell
python main\run_e2e.py `
  --case "spec\data\nas_samples\stage1\1-email-fastmail-1" `
  --output-dir "artifacts\smoke_fastmail" `
  --vision `
  --vlm-dry-run `
  --max-vlm-frames 4 `
  --vlm-workers 1 `
  --no-neo4j-log-miner
```

真实单 case：

```powershell
python main\run_e2e.py `
  --case "spec\data\nas_samples\stage1\1-email-fastmail-1" `
  --output-dir "artifacts\real_fastmail" `
  --vision `
  --max-vlm-frames -1 `
  --vlm-grid-layout "4x1" `
  --vlm-workers 2 `
  --no-neo4j-log-miner
```

只分析日志：

```powershell
python main\run_e2e.py `
  --log "D:\samples\logs.json" `
  --output-dir "artifacts\log_only"
```

### 2.3 批量 Debug

```powershell
python main\run_e2e.py `
  --case-root "spec\data\nas_samples" `
  --case-workers 2 `
  --output-dir "artifacts\batch_debug" `
  --vision `
  --vlm-dry-run `
  --max-vlm-frames 4 `
  --no-neo4j-log-miner
```

筛选 case 时，先创建 `artifacts\cases.txt`，每行一个相对 case ID：

```text
stage1/1-email-fastmail-1
stage2/2-filestruct-pdfconvert-2
```

```powershell
python main\run_e2e.py `
  --case-root "spec\data\nas_samples" `
  --case-list "artifacts\cases.txt" `
  --case-workers 2 `
  --output-dir "artifacts\selected_debug" `
  --vision `
  --vlm-dry-run
```

### 2.4 Release / 全量

只构建预计算缓存：

```powershell
python main\run_e2e.py `
  --case-root "spec\data\nas_samples" `
  --release `
  --release-precompute-only `
  --case-workers 4 `
  --output-dir "artifacts\release_precompute"
```

使用缓存执行 Release：

```powershell
python main\run_e2e.py `
  --case-root "spec\data\nas_samples" `
  --release `
  --vision-precompute-root "artifacts\release_precompute\vision_precompute" `
  --case-workers 2 `
  --vlm-workers 2 `
  --vlm-grid-layout "4x1" `
  --output-dir "artifacts\release"
```

一键全量运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools\run_all.ps1 `
  -CaseRoot "spec\data\nas_samples" `
  -RunDir "artifacts\full_release" `
  -PrecomputeWorkers 4 `
  -VlmCaseWorkers 2 `
  -VlmWorkers 2 `
  -VlmGridLayout "4x1"
```

## 4. 结果与续跑

单 case 的详细目录包含 `keyframes_raw_all/`、`keyframes_raw/`、`keyframe_duplicates.json`、`frame_observations.json`、`event_correlator_details.json`、`leak_paths.json` 和 `verdict_check.json`。

Release 中失败 case 会写入 `release_retry_cases.txt`，不会被当成阴性。恢复 VLM 配额后，将该列表和原目录的 `vision_precompute/` 传给新的 Release 输出目录即可续跑。

最终结论和事实链排障说明见 [04事实收集及证据链推理](04事实收集及证据链推理)。
