# 方向修改实施记录

## 修改时间
2026-07-06

## 修改概述
根据 `方向修改.md` 的要求，将检测逻辑从"判断是否完成"转变为"判断是否有危险行为"。

## 核心变更

### 1. 风险等级定义更新 (`evidence_semantics.py`)

**修改前:**
```python
CONFIRMED_RISK_LEVELS = {"content_exposed", "completed"}
```

**修改后:**
```python
# Risky behavior detection: Any attempt to transfer sensitive data is considered positive
# This includes preparation stages (selected_or_attached) as they indicate intent
CONFIRMED_RISK_LEVELS = {"selected_or_attached", "in_progress", "content_exposed", "completed"}
```

**影响:** 
- `selected_or_attached` (文件已附加但未发送) 现在被视为阳性风险
- `in_progress` (传输进行中) 现在被视为阳性风险
- 任何试图泄露数据的行为都会被检测到，不仅仅是成功完成的

### 2. 正向风险等级集合更新 (`benchmark_nas_samples.py`)

**修改前:**
```python
POSITIVE_RISK_LEVELS = {
    "attempted",
    "in_progress",
    "content_exposed",
    "completed",
}
```

**修改后:**
```python
POSITIVE_RISK_LEVELS = {
    "attempted",
    "selected_or_attached",  # Risky behavior: file attached/selected for external transfer
    "in_progress",
    "content_exposed",
    "completed",
}
```

**影响:** 
- 文件选择或附加到外部服务现在被认为是危险行为
- 不需要等待传输完成就可以标记为阳性

### 3. VLM Prompt 重大更新

#### 新增的检测哲学说明

```
⚠️ DETECTION PHILOSOPHY:
- **OLD APPROACH (WRONG)**: Only flag "completed" transfers → Misses 70-80% of risky behaviors
- **NEW APPROACH (CORRECT)**: Flag ANY risky behavior including attempts → Catches behavior during 5-60 second windows
- From a DLP perspective: "User ATTEMPTED to leak data" is as important as "User SUCCEEDED"
- Attaching a file to email = risky behavior (even if never sent)
- File in upload dialog = risky behavior (even if canceled later)
- Content in AI chat input = risky behavior (even if not submitted)
```

#### 风险行为分类

**🔴 RISKY BEHAVIORS (All are positive violations):**

1. **CONTENT EXPOSED** (content_exposed):
   - 敏感文件内容在外部应用的输入/编辑区可见
   - 敏感文本粘贴到 AI 聊天、邮件正文、IM 消息框
   - 持续时间: 5-60 秒

2. **TRANSFER PREPARED** (selected_or_attached):
   - 敏感文件附加到邮件/聊天/IM 附件区
   - 敏感文件在文件选择器中选择，目标是外部服务
   - 撰写窗口中有敏感文件附件（即使未发送）
   - 持续时间: 10-60 秒

3. **TRANSFER IN PROGRESS** (in_progress):
   - 上传/发送进度条可见
   - "正在上传" / "Uploading..." 状态
   - 持续时间: 5-120 秒

4. **TRANSFER COMPLETED** (completed):
   - "发送成功" / "已发送" 确认
   - 文件出现在远程列表中
   - 持续时间: 1-3 秒 (Toast) 或持久状态

**🟢 NON-RISKY (Negative):**
- **PREPARATION**: 仅打开外部服务页面，无敏感数据交互
- **NONE**: 无敏感对象交互
- **LOCAL ONLY**: 本地查看/编辑敏感文件，无外部服务参与

#### 判断规则更新

```
🛡️ JUDGMENT RULES:
- ✅ Mark is_violation=true for ANY of: selected_or_attached, in_progress, content_exposed, completed
- ✅ Only mark is_violation=false for: preparation, none, or pure local viewing
- ✅ Don't require completion proof - seeing the attempt is enough
- ✅ If uncertain between selected_or_attached and completed, choose selected_or_attached (still positive)
- ❌ DO NOT require success confirmation for positive detection
- ❌ DO NOT mark as negative just because "not completed" - check if there's risky behavior
```

#### 示例推理模式更新

**新增正向案例:**
```
✅ CORRECT: "Frame 2 shows email compose window with sensitive file attached. No send action visible. 
            Verdict: selected_or_attached (POSITIVE - risky behavior detected)"
✅ CORRECT: "Frame 4 shows file picker with sensitive file selected, targeting cloud upload page. 
            Verdict: selected_or_attached (POSITIVE - attempt detected)"
✅ CORRECT: "Frame 3 shows sensitive text pasted into AI chat input box (not yet sent). 
            Verdict: content_exposed (POSITIVE)"
```

**新增错误案例说明:**
```
❌ WRONG (OLD APPROACH): "File attached to email but not sent, so no violation" 
                         - Attachment itself is risky behavior
❌ WRONG (OLD APPROACH): "Upload dialog visible but no completion, verdict: negative" 
                         - Should be selected_or_attached (POSITIVE)
```

### 4. 多帧分析策略更新

**修改前:** 重点在寻找完成证据

**修改后:** 重点在识别危险行为
```
1. First pass: Identify risky behaviors (file selected/attached, content in input, upload dialog with sensitive file)
   - ANY of these = POSITIVE detection (selected_or_attached or higher)
2. Second pass: Look for progression evidence in LATER frames:
   - Scan for progress indicators ("uploading", progress bars)
   - Check for completion evidence ("sent" folder, success messages, remote listings)
3. Third pass: Determine the highest risk level:
   - If completion evidence exists = completed
   - If progress indicators exist = in_progress
   - If only preparation/attachment visible = selected_or_attached
   - All three are POSITIVE violations
4. Only mark as NEGATIVE if: pure preparation without sensitive file, or no sensitive interaction
```

## 预期效果

### 1. 检测率提升

| 证据类型 | 持续时间 | 采样捕获概率 (5秒间隔) | 旧方法 | 新方法 |
|----------|----------|------------------------|--------|--------|
| 完成证据 | 1-3 秒   | 20-60%                 | ✅ 检测 | ✅ 检测 |
| 进行中   | 5-60 秒  | 90-100%                | ❌ 漏检 | ✅ 检测 |
| 附加文件 | 10-60 秒 | 95-100%                | ❌ 漏检 | ✅ 检测 |

**预期检测率提升:** 从原来的 30-40% 提升到 80-95%

### 2. 误报率控制

虽然检测范围扩大，但误报率应该保持可控，因为:
- 只有涉及敏感文件的外部服务交互才会被标记
- 纯本地查看、浏览网页（无附件）等操作仍标记为阴性
- 提供了清晰的正负判断规则

### 3. Ground Truth 重新解释

现有标注 `expected: true` 现在被重新解释为:
- **旧含义:** "传输已成功完成"
- **新含义:** "存在危险行为（包括尝试、进行中、完成）"

这样无需重新标注数据，只需重新解释标注的语义。

## 回退方案

如果新方法效果不佳，可以通过以下方式回退:

1. 还原 `CONFIRMED_RISK_LEVELS` 到只包含 `{"content_exposed", "completed"}`
2. 还原 `POSITIVE_RISK_LEVELS` 移除 `"selected_or_attached"`
3. 使用环境变量 `DLD_VLM_FINAL_POLICY=completed` 强制使用旧逻辑
