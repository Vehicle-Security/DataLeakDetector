## 敏感文件的判定依据（核心是 **路径匹配** ）

当前项目判定敏感文件是 **基于完整文件路径的匹配** ，分为以下层次：

### 1. **初始敏感文件列表的建立**

 **三个来源** （优先级从高到低）：

#### a) Groundtruth 标注（测试数据）

```json
{
  "operations": [{
    "sensitive_file_path": "C:/Users/LENOVO/Desktop/公司财务报告.docx"
  }]
}
```

* 这是**预先配置**的敏感文件清单
* 用于测试评估时的标准答案

#### b) 日志中的关键词匹配（发现新的敏感文件）

函数：`_sensitive_files_from_logs()`

* 扫描日志中的文件路径
* 如果文件名或内容预览包含敏感关键词 → 将该路径加入敏感文件列表
* 例如：`D:/文档/薪资表.xlsx` 因为包含"薪资"而被识别

#### c) Fallback 降级（补充机制）

* 当预期是阳性但找不到敏感文件时使用

### 2. **运行时的路径匹配逻辑**

关键函数：`_is_sensitive_path()` 和 `_configured_sensitive_file_from_log()`

 **匹配规则** （第593-600行，606-629行）：

```python
def _is_sensitive_path(self, path: str, log: Dict[str, Any]) -> bool:
    path_key = file_key(path)
    name = log.get("file_name") or basename(path)
  
    # 1. 精确路径匹配
    if path_key in self.sensitive_file_keys:
        return True
  
    # 2. 文件名匹配
    if basename(path).lower() in self.sensitive_basenames:
        return True
  
    # 3. 排除系统噪音
    if is_system_noise_path(path):
        return False
  
    # 4. 关键词匹配（作为补充）
    return is_sensitive_name(name)
```

 **配置的敏感文件匹配** （更宽松的模糊匹配）：

```python
def _configured_sensitive_file_from_log(self, log: Dict[str, Any]) -> str:
    text = " ".join([
        log.get("file_path", ""),
        log.get("file_name", ""),
        log.get("content_preview", ""),
        log.get("window_title", "")
    ])
  
    for configured_path in self.sensitive_files:
        # 检查路径键是否包含
        if configured_key in file_key(text):
            return configured_path
  
        # 检查文件名是否包含
        if configured_base in text.lower():
            return configured_path
  
        # 检查文件主干名（去掉空格等）
        if len(configured_stem) >= 4 and configured_stem in compact_text:
            return configured_path
  
    return ""
```

## 实际工作流程

```
1. 系统启动时建立敏感文件列表：

   sensitive_files = [
       "C:/Users/LENOVO/Desktop/公司财务报告.docx",  // 来自 groundtruth
       "D:/项目/薪资表.xlsx"                          // 来自日志关键词
   ]

2. 处理每条日志时：
   - 提取文件路径：log.get("file_path")
   - 匹配判定：_is_sensitive_path(path)
     → 完整路径匹配 ✅
     → 文件名匹配 ✅ (如 "公司财务报告.docx")
     → 路径包含 ✅ (如日志显示 "...Desktop/公司财务报告.docx...")
     → 文件主干匹配 ✅ (去除空格后的模糊匹配)

3. 如果匹配成功 → 这个操作涉及敏感文件
```

## 系统**有考虑**截图/复制内容等衍生场景，但依赖推理过程识别

### 1. **截图和屏幕共享**

系统将这些视为 **内容暴露** ，而不是传统的文件衍生：

```python
# 在 action_type 中专门定义（第6298行）
leak_action_types = {
    "screenshot",          # 截图
    "screen_share",        # 屏幕共享
    "screen_record",       # 屏幕录制
    "external_exposure",   # 外部暴露
    ...
}
```

 **特点** ：

* 这些操作直接生成 `LeakFile` 事实（作为泄露通道）
* 不产生新的文件路径，而是使用 `shared_data` 或 `clipboard_data` 字段
* 泄露通道标记为 "screenshot"、"screen_share" 等

### 2. **剪贴板复制内容**

系统通过 **ClipboardWrite/ClipboardRead** 机制追踪（第6220-6224行）：

```python
# 剪贴板操作
if action_type == "copy_content":
    add("ClipboardWrite", (op_id, process, data, timestamp))
elif action_type == "paste_content":
    add("ClipboardRead", (op_id, process, data, timestamp))
```

 **污点传播** ：

```
敏感文件 → 复制内容 → ClipboardWrite → ClipboardRead → 粘贴到新位置
```

Datalog 规则会自动将剪贴板操作转换为 `CrossProcessTransfer`（taint_rules.dl 第39-44行）：

```datalog
CrossProcessTransfer(write_id_read_id, p_write, p_read, data, read_ts) :-
    ClipboardWrite(write_id, p_write, data, write_ts),
    ClipboardRead(read_id, p_read, data, read_ts),
    read_ts > write_ts,
    read_ts - write_ts < 300000,  // 5分钟内
    p_write != p_read.
```

### 3. **复制内容另存为新文件**

通过 `action_type` 识别（第6000-6005行）：

```python
LOG_RULE_DEFAULTS = {
    "variant_created": ("save_as", "selected_or_attached", False),
    "clipboard_content": ("copy_content", "selected_or_attached", False),
    "convert_created": ("convert_file", "selected_or_attached", False),
    ...
}
```

 **处理方式** ：

* VLM 分析识别 "另存为" 操作
* 生成 audit action，包含 `source_file` 和 `derived_file`
* 转换为 `TransferFile` 事实（第6279-6290行）

### 4. **关键机制：`shared_data` 和 `clipboard_data` 字段**

系统用这些字段追踪**不是文件路径**的衍生内容（第6108-6112行）：

```python
def _action_shared_data_field(action: Dict[str, Any]) -> str:
    for key in ("shared_data", "clipboard_data", "data", "source_file", "derived_file"):
        value = str(action.get(key, "") or "").strip()
        if value:
            return value
    return ""
```

 **使用场景** ：

* 截图内容：`shared_data = "screenshot_of_敏感文件.png"`
* 剪贴板文本：`clipboard_data = "敏感文件的部分内容"`
* 屏幕共享：`shared_data = "screen_content"`

### 5. **敏感性判断逻辑**

关键代码（第6206-6210行）：

```python
if (
    not _is_sensitive_ref(source_file, sensitive_files)
    and not _is_sensitive_ref(derived_file, sensitive_files)
    and not _is_sensitive_ref(action_text, sensitive_files)  # 包含 shared_data/clipboard_data
):
    continue  # 跳过不涉及敏感文件的操作
```

 **判断方式** ：

* 检查 `source_file`（原始敏感文件）
* 检查 `derived_file`（衍生文件路径）
* 检查 `action_text`（包括 shared_data/clipboard_data/description）

如果 action_text 中包含敏感文件名的片段 → 认为是衍生内容

### 6. **实际工作流程示例**

**场景：用户打开敏感文件，复制内容，粘贴到 ChatGPT**

```
1. OpenFile:
   - 打开 "公司财务报告.docx"
   - 生成: OpenFile("op1", "word.exe", "公司财务报告.docx", ts1)

2. Copy Content (用户选中并复制):
   - VLM 识别为 copy_content
   - 生成: ClipboardWrite("op2", "word.exe", "公司财务报告.docx", ts2)
   - clipboard_data: "财务数据..."

3. Paste Content (粘贴到 ChatGPT):
   - VLM 识别为 paste_content 到 AI 服务
   - 生成: ClipboardRead("op3", "chrome.exe", "公司财务报告.docx", ts3)
   - action_type: "external_exposure"

4. Datalog 推理:
   - Tainted("word.exe", "公司财务报告.docx", "op1", ts1)  # 污点源
   - CrossProcessTransfer("op2_op3", "word.exe", "chrome.exe", "公司财务报告.docx", ts3)  # 剪贴板传播
   - Tainted("chrome.exe", "公司财务报告.docx", "op1 -> op2_op3", ts3)  # 污点传播
   - LeakFile("op3", "chrome.exe", "公司财务报告.docx", "external_exposure", ts3)  # 泄露检测
   - SearchLeak(...)  # 泄露路径
```
