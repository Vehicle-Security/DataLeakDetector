# 帧调试图片保存功能使用说明

## 概述

优化后的基准测试支持将选中的帧保存为 JPEG 缩略图，方便可视化调试和分析抽帧策略。

---

## 启用方式

### 环境变量

```bash
# 启用帧调试图片保存
export DLD_SAVE_FRAME_DEBUG=1

# 可选：启用帧上的元数据覆盖（默认启用）
export DLD_FRAME_DEBUG_OVERLAY=1

# 运行测试
python tools/benchmark_nas_samples.py \
  --use-vlm \
  --vlm-gate-mode adaptive \
  --vlm-workers 12 \
  --json-output "spec/output/test_with_debug/report.json"
```

### Windows (PowerShell)

```powershell
$env:DLD_SAVE_FRAME_DEBUG="1"
$env:DLD_FRAME_DEBUG_OVERLAY="1"

python tools/benchmark_nas_samples.py `
  --use-vlm `
  --vlm-gate-mode adaptive `
  --vlm-workers 12 `
  --json-output "spec/output/test_with_debug/report.json"
```

    │   ├── vlm_seg_01_frame_00145_event_anchor_CONTEXT.jpg
    │   ├── vlm_seg_01_timeline.txt

### 文件命名规则

```
{segment_id}_frame_{frame_index:05d}_{selection_hint}_{status}.jpg
```

- **segment_id**: 段ID（如 `vlm_seg_01`, `vlm_seg_02`）
- **frame_index**: 视频中的帧索引（5位数字，如 `00120`）
- **selection_hint**: 选择提示（简化版）
  - `completion_anchor`: 完成事件锚点 ⭐
  - `event_anchor`: 一般事件锚点
  - `terminal_completed`: 终止状态锚点
  - `window_start` / `window_end`: 窗口边界
  - `scene_change`: 场景变化
- **status**: 发送状态
  - `SENT`: 已发送给 VLM（包含图像数据）
  - `CONTEXT`: 仅上下文（未发送图像，只有元数据）

### Timeline 文件

每个段都有一个 `{segment_id}_timeline.txt` 文件，包含该段所有帧的详细信息：

```text
Segment: vlm_seg_02
Case: stage1\1-email-163email-2
Total frames: 12
Sent to VLM: 8

================================================================================

Frame 1/12:
  Index: 320
  Timestamp: 2026-03-08 12:14:05
  Selection Hint: completion_anchor_transfer:send_message
  Selection Reason: completion_anchor+event_anchor
  Image Priority: 13.50
  Scene Score: 0.8234
  Status Score: 0.4512
  Sent to VLM: True
  OCR Ran: True
  OCR Flags: sensitive_name_visible

Frame 2/12:
  Index: 325
  Timestamp: 2026-03-08 12:14:08
  Selection Hint: completion_anchor_transfer:send_message
  Selection Reason: completion_anchor
  Image Priority: 13.20

  Sent to VLM: True
  OCR Ran: True
```

## 图片特性

### 尺寸和质量

- **最大边长**: 800px（自动缩放，保持宽高比）
- **JPEG 质量**: 85
- **存储空间**: 每帧约 50-150KB

### 元数据覆盖（可选）

启用 `DLD_FRAME_DEBUG_OVERLAY=1` 后，图片左上角会叠加显示：

```
Frame: 320
Time: 2026-03-08 12:14:05
Hint: completion_anchor
Priority: 13.5
Scene: 0.82
```

这样可以不用打开 timeline 文件就能快速识别帧的关键信息。

## 使用场景

### 场景 1: 分析 FN 漏报案例的抽帧问题

**问题**: 邮件案例 `1-email-163email-2` 被判断为未发送，但实际已发送。

**步骤**:

1. **打开案例的调试目录**:
   ```
   spec/output/test_with_debug/frame_debug/stage1__1-email-163email-2/
   ```

2. **查看所有帧的缩略图**:
   - 用文件管理器的缩略图模式浏览所有 JPEG
   - 快速识别哪些帧显示了"已发送列表"或"上传完成"

3. **重点检查 completion_anchor 帧**:
   ```
   vlm_seg_02_frame_00320_completion_anchor_SENT.jpg
   vlm_seg_02_frame_00325_completion_anchor_SENT.jpg
   ```
   - 这些帧是否真的显示了完成后的状态？
   - 还是只显示了准备阶段（撰写窗口、上传对话框）？

4. **对比 Ground Truth 时间**:
   - Ground Truth: 泄露时间 12:14:01-02
   - Frame 320: 时间戳 12:14:05（泄露后 3 秒）
   - 检查这个时间的帧是否显示了"已发送"状态

5. **查看 timeline.txt 确认细节**:
   ```bash
   cat vlm_seg_02_timeline.txt
   ```

### 场景 2: 验证完成锚点是否生效

**目标**: 检查优化后，完成事件锚点是否真的被密集采样了。

**步骤**:

1. **统计 completion_anchor 帧数量**:
   ```bash
   find frame_debug -name "*completion_anchor*" | wc -l
   ```

2. **查看具体案例的分布**:
   ```bash
   ls -lh frame_debug/stage1__1-email-163email-2/ | grep completion_anchor
   ```
   应该看到多个连续的帧（前后 ±5 秒密集采样）

3. **可视化检查**:
   - 打开所有 `*completion_anchor_SENT.jpg` 图片
   - 看看它们是否覆盖了从"准备"到"完成"的完整过程

### 场景 3: 对比优化前后的抽帧差异

**目标**: 对比窗口扩展和完成锚点优化前后的帧选择变化。

**步骤**:

1. **运行优化前的测试**（使用旧代码）:
   ```bash
   git checkout HEAD~1 tools/benchmark_nas_samples.py
   DLD_SAVE_FRAME_DEBUG=1 python tools/benchmark_nas_samples.py ... \
     --json-output "spec/output/before_optimization/report.json"
   ```

2. **运行优化后的测试**（使用新代码）:
   ```bash
   git checkout HEAD tools/benchmark_nas_samples.py
   DLD_SAVE_FRAME_DEBUG=1 python tools/benchmark_nas_samples.py ... \
     --json-output "spec/output/after_optimization/report.json"
   ```

3. **对比同一案例的帧**:
   ```bash
   # 优化前
   ls spec/output/before_optimization/frame_debug/stage1__1-email-163email-2/

   # 优化后
   ls spec/output/after_optimization/frame_debug/stage1__1-email-163email-2/
   ```

4. **关键对比点**:
   - 优化后是否有更多 `completion_anchor` 帧？
   - 优化后的帧时间范围是否更长（窗口扩展生效）？
   - 优化后是否覆盖了关键的"完成后"时刻？

### 场景 4: 制作案例演示或报告

将帧图片用于：
- 可视化展示抽帧策略的工作原理
- 制作 PPT 演示优化效果
- 撰写技术报告的配图

**示例**:
```
[优化前] → 只采样到准备阶段
[图片: vlm_seg_02_frame_00280_event_anchor_SENT.jpg - 显示撰写窗口]

[优化后] → 采样到完成状态
[图片: vlm_seg_02_frame_00320_completion_anchor_SENT.jpg - 显示已发送列表]
```

## 性能影响

### 存储空间

- **每个案例**: 约 5-20 MB（取决于帧数）
- **完整测试（230 案例）**: 约 2-5 GB

### 运行时间

- **帧保存时间**: 每帧约 5-10ms
- **总体影响**: < 5%（相比 VLM API 调用时间可忽略）

### 建议

- ✅ **调试阶段**: 启用帧保存，便于问题排查
- ✅ **优化验证**: 启用帧保存，对比优化前后
- ⚠️ **生产运行**: 可以禁用以节省空间

## 常见问题

### Q1: 为什么有些帧标记为 CONTEXT 而不是 SENT？

**原因**: 
- VLM 有图像数量限制（如 12 帧/段）
- OCR 预过滤可能排除了一些帧
- 优先级排序后，低优先级的帧只作为上下文

**查看方法**:
```bash
# 统计发送和上下文帧的比例
ls frame_debug/stage1__1-email-163email-2/ | grep SENT | wc -l
ls frame_debug/stage1__1-email-163email-2/ | grep CONTEXT | wc -l
```

### Q2: 如何只保存失败案例的帧？

**方法 1**: 修改代码，添加条件判断（需要在结果已知后重新提取）

**方法 2**: 运行后手动筛选
```bash
# 从 report.json 提取 FN 案例列表
python -c "
import json
report = json.load(open('report.json'))
fn_cases = [c['case'].replace('\\\\', '__').replace('/', '__') for c in report['cases'] if c['final_bucket'] == 'fn']
print('\\n'.join(fn_cases))
" > fn_cases.txt

# 只保留 FN 案例的调试目录
cd frame_debug
find . -maxdepth 1 -type d | grep -v -f ../fn_cases.txt | xargs rm -rf
```

### Q3: 元数据覆盖遮挡了重要内容怎么办？

**解决方案**: 禁用覆盖
```bash
export DLD_FRAME_DEBUG_OVERLAY=0
```

原始帧会保存，所有元数据在 `timeline.txt` 中仍然可见。

### Q4: 如何批量导出所有 completion_anchor 帧？

```bash
# 创建专门的目录
mkdir -p frame_debug/completion_anchors_only

# 复制所有 completion_anchor 帧
find frame_debug -name "*completion_anchor*" -type f -exec cp {} frame_debug/completion_anchors_only/ \;

# 按案例分组
for case in frame_debug/*/; do
  case_name=$(basename "$case")
  mkdir -p "frame_debug/completion_anchors_by_case/$case_name"
  cp "$case"/*completion_anchor* "frame_debug/completion_anchors_by_case/$case_name/" 2>/dev/null
done
```

## 与 report.json 的关联

帧调试图片与 `report.json` 中的 `frame_selection_debug` 字段完全对应：

```python
import json
from pathlib import Path

report = json.load(open('report.json'))
case = next(c for c in report['cases'] if c['case'] == 'stage1\\1-email-163email-2')

# 从 JSON 获取帧信息
for segment in case['frame_selection_debug']['segments']:
    segment_id = segment['segment_id']
    for frame in segment['frame_details']:
        frame_index = frame['frame_index']
        hint = frame['selection_hint'].split(':')[0]
        sent = '_SENT' if frame['image_sent'] else '_CONTEXT'
        
        # 构造文件名
        case_name = case['case'].replace('\\', '__')
        filename = f"{segment_id}_frame_{frame_index:05d}_{hint}{sent}.jpg"
        filepath = Path(f"frame_debug/{case_name}/{filename}")
        
        print(f"Frame {frame_index}: {filepath.exists()} - {frame['timestamp']}")
```
