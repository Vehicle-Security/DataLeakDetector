# 帧选择调试信息使用指南

## 概述

优化后的基准测试现在会在 `report.json` 中记录详细的帧选择信息，方便调试和分析抽帧策略。

---

## 调试信息结构

### 1. 案例级别的帧选择信息

每个案例的 `frame_selection_debug` 字段包含：

```json
{
  "frame_selection_debug": {
    "segment_plan": {
      "raw_windows": 24,
      "merged_windows": 1,
      "split_segments": 4,
      "selected_segments": 4,
      "merge_gap_seconds": 8,
      "segment_seconds": 45,
      "overlap_seconds": 10,
      "segments": [
        {
          "start": "2026-03-08 12:12:35",
          "end": "2026-03-08 12:13:20",
          "duration_seconds": 45.0,
          "candidate_events": 1,
          "log_hits": 30,
          "score": 17.75
        }
      ]
    },
    "segments": [
      {
        "segment_id": "vlm_seg_01",
        "window": ["2026-03-08 12:12:35", "2026-03-08 12:13:20"],
        "frame_details": [
          {
            "frame_index": 120,
            "timestamp": "2026-03-08 12:12:45.123",
            "selection_reason": "completion_anchor+event_anchor",
            "selection_hint": "completion_anchor_transfer:upload_complete",
            "image_priority": 13.5,
            "scene_score": 0.82,
            "status_region_score": 0.45,
            "image_sent": true,
            "ocr_ran": true,
            "ocr_flags": ["sensitive_name_visible"]
          }
        ]
      }
    ]
  }
}
```

### 2. 字段说明

#### Segment Plan（窗口规划）
- **raw_windows**: 原始候选窗口数量
- **merged_windows**: 合并后的窗口数量
- **split_segments**: 分割后的段数量
- **selected_segments**: 最终选择的段数量
- **segments**: 每个段的时间范围、事件数、日志命中数、评分

#### Frame Details（帧详情）
- **frame_index**: 视频中的帧索引
- **timestamp**: 精确时间戳
- **selection_reason**: 选择原因（组合）
  - `completion_anchor`: 完成事件锚点（最高优先级）⭐
  - `terminal_*`: 终止状态锚点
  - `event_anchor`: 一般事件锚点
  - `window_start/end`: 窗口边界
  - `scene_change`: 场景变化
- **selection_hint**: 原始提示（更详细）
  - `completion_anchor_transfer:upload_complete`: 上传完成锚点
  - `completion_anchor_transfer:send_message`: 消息发送锚点
  - `terminal_completed`: 终止完成状态
- **image_priority**: 图像优先级（0-15+）
  - 10: completion_anchor 基础分
  - 4: OCR 风险命中
  - 3.5: 事件锚点
  - 3: 窗口边界
  - 2+: 场景变化
- **scene_score**: 场景变化评分（0-1）
- **status_region_score**: 状态区域评分（0-1）
- **image_sent**: 是否发送给 VLM
- **ocr_ran**: 是否运行 OCR
- **ocr_flags**: OCR 检测到的标记

## 使用场景

### 场景 1: 分析 FN（漏报）案例的抽帧问题

**问题**：某个邮件案例被 VLM 判断为"未发送"，但实际已发送。

**分析步骤**：

1. 找到该案例的 `frame_selection_debug`
2. 检查 `segment_plan.segments`：
   - 窗口是否覆盖了 Ground Truth 的泄露时间？
   - 窗口结束时间是否延长到了完成后 30 秒？
3. 检查 `frame_details`：
   - 有多少帧的 `selection_hint` 包含 `completion_anchor`？
   - 这些帧的 `timestamp` 是否在泄露时间之后？
   - 这些帧是否 `image_sent: true`？
4. 对比 VLM 的判断：
   - 查看 `vlm_reasons`，VLM 看到了什么？
   - 如果 VLM 说"邮件窗口为空"，检查是否有帧在"已发送列表"时刻

**示例分析**：

```python
import json

report = json.load(open('report.json'))
fn_case = next(c for c in report['cases'] if c['case'] == 'stage1\\1-email-163email-2')

# 检查窗口扩展
segment_plan = fn_case['frame_selection_debug']['segment_plan']
for seg in segment_plan['segments']:
    print(f"Segment: {seg['start']} - {seg['end']} ({seg['duration_seconds']}s)")
    # 是否覆盖了泄露时间 12:14:01-02？
    # 是否延长到了 12:14:30+ ？

# 检查完成锚点
for segment in fn_case['frame_selection_debug']['segments']:
    completion_frames = [
        f for f in segment['frame_details'] 
        if 'completion_anchor' in f['selection_hint']
    ]
    print(f"{len(completion_frames)} completion anchor frames")
    for f in completion_frames:
        print(f"  Frame {f['frame_index']}: {f['timestamp']} - {f['selection_hint']}")
```

### 场景 2: 验证优化是否生效

**验证窗口扩展**：

```python
# 优化前 vs 优化后
old_report = json.load(open('old_report.json'))
new_report = json.load(open('new_report.json'))

for old_case, new_case in zip(old_report['cases'], new_report['cases']):
    if old_case['case'] != new_case['case']:
        continue
    
    old_segments = old_case['vlm_frame_budget']['segment_plan']['segments']
    new_segments = new_case['frame_selection_debug']['segment_plan']['segments']
    
    for old_seg, new_seg in zip(old_segments, new_segments):
        old_duration = old_seg['duration_seconds']
        new_duration = new_seg['duration_seconds']
        if new_duration > old_duration:
            print(f"{old_case['case']}: 窗口扩展 {old_duration}s -> {new_duration}s (+{new_duration - old_duration}s)")
```

**验证完成锚点**：

```python
completion_anchor_count = 0
for case in new_report['cases']:
    if not case.get('frame_selection_debug'):
        continue
    for segment in case['frame_selection_debug']['segments']:
        for frame in segment['frame_details']:
            if 'completion_anchor' in frame['selection_hint']:
                completion_anchor_count += 1

print(f"Total completion anchor frames: {completion_anchor_count}")
```

### 场景 3: 导出帧选择时间线

生成可视化的时间线，查看帧分布：

```python
import matplotlib.pyplot as plt
from datetime import datetime

case = report['cases'][42]  # FN 案例
segments = case['frame_selection_debug']['segments']

fig, ax = plt.subplots(figsize=(15, 5))

for seg_idx, segment in enumerate(segments):
    frames = segment['frame_details']
    for frame in frames:
        ts = datetime.fromisoformat(frame['timestamp'])
        priority = frame['image_priority']
        color = 'red' if 'completion_anchor' in frame['selection_hint'] else 'blue'
        marker = 'o' if frame['image_sent'] else 'x'
        ax.scatter(ts, seg_idx, s=priority * 20, c=color, marker=marker, alpha=0.7)

ax.set_xlabel('Time')
ax.set_ylabel('Segment Index')
ax.set_title(f"Frame Selection Timeline: {case['case']}")
plt.show()
```

## 优化验证清单

使用帧选择调试信息验证优化效果：

- [ ] **窗口扩展生效**：检查有准备动作的案例，窗口是否延长了 30 秒
- [ ] **完成锚点存在**：FN 案例中是否有 `completion_anchor` 帧
- [ ] **完成锚点被发送**：`completion_anchor` 帧的 `image_sent` 是否为 `true`
- [ ] **完成锚点时机正确**：`completion_anchor` 的 `timestamp` 是否在泄露时间之后
- [ ] **优先级正确**：`completion_anchor` 的 `image_priority` 是否 >= 10
- [ ] **密集采样生效**：完成事件前后 ±5 秒是否有多个帧

## 常见问题排查

### Q1: 为什么有 completion_anchor 但 VLM 还是判断为"未发送"？

**可能原因**：
1. `completion_anchor` 帧的 `image_sent: false` - 被 OCR 过滤掉了
2. `completion_anchor` 帧的时间太早，还在准备阶段
3. 完成锚点的数量太少（< 3 帧）

**解决方法**：
- 增加 `completion_anchor` 的 `image_priority`
- 调整完成事件检测逻辑
- 增加密集采样的时间跨度

### Q2: 窗口没有扩展？

**检查**：
1. `segment_plan.segments` 中的 `duration_seconds` 是否增加？
2. 日志中是否有 `file_selected`、`attach_file` 等准备事件？

**可能原因**：
- 准备事件没有被识别
- 窗口已经够长，不需要扩展
- `DLD_COMPLETION_BUFFER_SECONDS` 环境变量设置错误

### Q3: 如何调整采样策略？

**环境变量**：
- `DLD_COMPLETION_BUFFER_SECONDS=30` - 完成后缓冲时间（15-60 秒）
- `DLD_VLM_REVIEW_CACHE=0` - 禁用缓存，测试新策略

**代码修改**：
- `_extend_segments_for_completion()` - 窗口扩展逻辑
- `_event_anchor_times()` - 完成事件锚点密集采样
- `is_critical_anchor()` - 锚点优先级
